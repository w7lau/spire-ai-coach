# 尖塔 AI 教练 · Spire AI Coach

《杀戮尖塔 2》的 AI 回合指导与本地战斗规划 Mod。配置自己的 API URL、模型和 Key 获取 AI 建议，或使用本地模拟规划整场战斗。AI 建议由玩家操作；本地已验证路线可点击“执行方案”自动出牌。

当前版本：**0.7.0，实验版**。已针对本机 `v0.111.0` 游戏程序集编译；游戏更新后可能需要重新编译或适配。

0.7.0 新增“执行方案”和“停止执行 · Esc”。仅点击后执行已验证的本地路线，逐步核对同场战斗、Mod、原生状态与操作历史；状态偏离、额外选择超时或战斗结束时停止。不自动执行 AI 回复，不领取战后奖励或选择地图。药水使用受计算时和当前开关共同约束。停止后已出手的动作继续正常结算，后续步骤不再执行。

进入单人战斗后会提前准备计算，资源准备和启动同时进行，多次计算复用已就绪的实例。首次加载游戏/Mod 仍需要时间；进度提示改为“准备计算”“正在计算”，具体试走过程可展开查看。

0.6.3 修复后台模拟进程继承主游戏存档句柄、导致过关后无法保存的问题。Windows 启动器现在明确禁止继承操作系统句柄，同时保留独立存档目录和禁用 Steam 的设置。升级前需要退出游戏并结束旧后台模拟；该修复不会重建此前保存失败的进度。

## 本地整场计算（0.6.2）

0.6.2 增加战术优先探索、分阶段耗时和路线续用。探索优先级依据目标生命/格挡、攻击意图、防御缺口、剩余可用手牌、增伤/易伤/回能预览和已知武装＋升级机制计算；它不是效果证明，不删除未知或低优先级动作。四分之一的首次探索忽略这个优先级，已执行分支仍由模拟结果反馈选路。普通武装等额外选牌仍不支持。

完整复核的路线保存逐步原生状态及操作历史指纹。手动按建议操作后，即使界面漏过中间几帧，只要仍在同一战斗、Mod 集合未变、历史与下一步状态同时一致，就继续显示剩余步骤，无需重新搜索；期间失血改为尚未执行部分的预计失血。动画/敌方回合暂停建议，偏离、未知历史、药水开关变化或无对应操作的状态变化都使路线失效。自动执行则必须逐步匹配，不允许跳过未授权的中间动作。

和 AI 指导共用一个安装包、F8 面板与状态过期检查。点击「本地整场计算（实验）」即可使用，不需要 URL、模型、Key，也不会调用 AI。结果可用后点击「执行方案」执行，或自己按建议操作。F9 仍调用原来的 AI 本回合指导；原有设置保留。

后台在游戏安装目录的同级 `.spire-ai-coach-workers` 中建立独立启动目录。EXE、PCK 和游戏运行库使用同盘 NTFS 硬链接共享，不再复制完整游戏资源；Mod 文件、APPDATA、存档及日志保持独立。删除后台链接不删除原始资源，但共享文件不是写隔离沙箱，后台代码不得修改游戏二进制。准备失败时明确报错，不悄悄退回全量复制。安装脚本会清理旧版带所有权标记且未占用的资源副本，保留诊断。

面板并发设为 `0` 时，根据逻辑处理器数和可用内存选择 1–8 路，预留约 3 GB、每路按约 1.5 GB 估算；也可手动选择 1–16 路并立即用于下一次计算，点击旁边的「保存本地设置」可持久化，不需要先配置 AI。无界面仍需运行独立游戏/Mod 堆，并发增加会消耗内存和 CPU。启动后的进程和已加载资源可以复用，闲置十分钟退出。

**后台静音**：独立用户目录在启动前关闭主音量、音乐、音效和环境音，工作进程中同时静音原生 FMOD 与 Godot 总线；Godot 使用 Dummy 音频驱动。不会修改前台游戏音量。

**药水开关**：「计算主动使用药水的路线」默认关闭。开启后按真实药水槽和合法目标枚举，调用原生使用、消耗及遗物钩子；同时仍搜索保留药水的路线，同等胜负、生命和永久收益时优先少用药水。关闭仅限制未来主动喝药，自动触发的仙灵药水等仍按游戏机制结算，已经喝过的药水也会在恢复历史时重放。需要额外选牌的药水尚不支持。开关可随并发一起保存。

**实时进度**：计算时自动展开后台进度，显示各进程当前路线、已评估/获胜数量；下拉选择进程可查看模拟回合、生命条、格挡、能量、手牌、状态效果、敌人属性及当前行动节点。最近 12 步按实际结算显示出牌/药水/结束回合及数值变化。预算条表示时间预算使用量，**不是穷举完成率**。这些是正在试走的分支，不是最终建议；完成时自动收起，可重新展开查看，取消或真实状态变化会清空过期过程。

每条路线从当前操作点连续模拟到战斗胜负，最多 **10 个玩家回合（含当前轮）**。每进程最多评估 32 条路线、每轮最多 24 次出牌/药水操作、搜索预算 60 秒，另有启动和最佳路线复核时间。使用原生抽牌、敌方行动及胜利结算，按回合列出具体步骤；胜利方案优先于未完成方案，胜利之间优先结算生命、最大生命、金币等。没有找到胜利时明确显示部分路线和轮数/时间/操作上限，不冒充打通整场。建议中的手牌位置指执行该步骤时的位置；同名敌人同时显示目标编号。按建议出牌后，历史与预测状态一致时自动续用剩余路线；偏离后清除建议，再重新计算。

**0.6.1 算法优化**：搜索改用结算反馈的操作树，取消“攻击 → 能力 → 技能”的固定排序。不同顺序先获得探索机会，再根据实际试走结果增加好分支的搜索机会；尚未执行的替代动作不继承其他路线的收益。结束回合与出牌共同参与选择，结算生命相同时优先少掉血，再比较其他收益、药水及操作数。每条路线只恢复一次，最多保留 8192 个树节点；完整模拟过的相同终止历史不再执行，时间截断不当作失败回传。不会仅因同名、零伤害或格挡已够而删除操作，也不会拿不含 Mod 私有状态的同步哈希合并局面。**这是预算内候选方案，不是全局最优。** 新搜索器完成定向逻辑测试；尚无新版原生吞吐或胜率对照。

后台读取原生战前重放记录，核对模型表、游戏/Mod 程序集及根状态，再模拟合法手牌与目标；正常完成后重新恢复并执行最佳路线，复核每步指纹和最终生命、敌人生命、金币、胜负。前台游戏不参与模拟出牌；继续操作或点击取消会停止本次任务。

当前只支持单人；含额外选牌/选择的历史记录暂不重放，候选执行遇到此类流程会停掉对应工作进程，最多保留此前完整结算的路线。Mod 用户档中的额外配置、任意私有/静态字段未被通用复制；相同指纹不证明这些字段完全一致。已启用的 Mod 会复制进后台，但不承诺所有 Mod 都能运行或恢复。错误/状态不一致时不发布该进程的结果，可以切回 AI。

奖励/成长机制的通用识别尚未实现，因此**本版始终按预算搜索，没有启用无伤提前停止**。相关规则和验收条件已保留在 [搜索规则](docs/local-search-policy.md)，不会因当前看似无伤就猜测没有奖励。

## 使用

1. 从本仓库 Releases 下载安装包，解压，将其中 `SpireAiCoach` 文件夹放进游戏的 `mods` 目录。
2. 最终结构应为 `Slay the Spire 2/mods/SpireAiCoach/SpireAiCoach.dll` 和同目录 `SpireAiCoach.json`。
3. 重启游戏，在 Mod 列表启用「尖塔 AI 教练」。不依赖 BaseLib，不需要 PCK。
4. 按 **F8** 展开面板，按 **F10** 打开设置，填写 URL、模型、API Key，点击「保存设置」。
5. 进入战斗，在自己的出牌阶段点击「AI 分析」或按 **F9**；也可以直接点击「本地计算（实验）」。
6. AI 正文会边接收边显示，接收期间标注尚未完成；完整回复通过校验后，自动整理为带卡牌名称和目标的出牌建议。再依次查看并手动操作。战斗状态变化时，旧建议会标记过期；遇到新抽牌、选牌或随机结果，可以重新分析。

API 支持 **Chat Completions 兼容协议**。URL 可以填 `https://你的服务商/v1` 或完整的 `/chat/completions` 地址。仅填域名时补上 `/v1/chat/completions`；自定义路径保持原前缀。支持本机 HTTP 服务，例如 `http://localhost:11434/v1`。纯 Anthropic Messages / Gemini 原生接口需要兼容网关，第一版没有其原生适配器。

每次点击 AI 分析产生一次请求；不会后台自动调用、自动重试或设置输出 token 上限。API 费用取决于你配置的服务商。默认超时 120 秒；可在本地配置中将 `timeout_seconds` 改为 10–600 秒。

默认使用 `stream=true`，支持 Chat Completions 的 SSE 流。取消、出牌导致状态变化、超时或断线都会停止本次接收，部分内容不会变成正式建议。若服务商忽略流式参数并一次性返回 JSON，会兼容读取这一次回复并在完成时注明，不再发起第二次请求。

固定游戏规则、指导职责和输出合同只放在稳定的首条 system 消息；实时战斗任务与快照放在之后的 user 消息。0.3.1 补齐默认能量刷新、抽牌弃牌、保留／虚无、格挡与伤害触发顺序，并明确“没有副作用的有益动作优先于浪费即将失效的能量”，同时保留反伤、能量保留等合理例外。

完成时显示输入、缓存命中和输出 token 数。默认请求 `stream_options.include_usage=true`；不兼容的接口可在设置中取消「请求流式用量统计」。未返回计数显示未知／未返回，不当作零。缓存命中依赖服务商、模型、相同前缀和缓存有效期等条件；固定 system 为缓存创造条件，但不保证命中或具体优惠。参见 [OpenAI 官方缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching)。不向第三方接口强加专属缓存参数，也不靠补无用文本凑缓存长度。

0.3.2 将消息顺序调整为「固定规则 → 角色与遗物 → 当前战斗状态」。角色与遗物以单独 user 消息放在回合、指纹和手牌等变化字段之前，动态快照中不重复发送。每次仍从同一份最新快照构造全部消息；遗物描述、计数或使用状态变化时同步更新，不为缓存冻结旧值。缓存可以覆盖 user 消息里的相同前缀，不需要把战斗数据提升成 system 指令；后续请求仍发送完整必要信息，不依赖服务商记住上一场战斗。

诊断面板直接展示解开日志和 HTTP 外层 JSON 后的 system / user 消息内容，避免原始诊断嵌套字符串产生大量反斜杠。复制完整诊断和本地文件仍保留原始传输证据。HTTP 包装所需的转义会由接口解析，不是模型额外读取的提示词字符；消息内部 JSON 文本中的引号、描述换行等必要转义仍保留，不能通过直接删除反斜杠压缩。

## 发送给 AI 的信息

- 当前回合、本人行动阶段、层数、进阶等级、生命、格挡、能量和星星。
- 本人的手牌、抽牌堆、弃牌堆、消耗牌堆和正在结算区：每张实例、总数、按卡牌和升级等级统计的数量。
- 卡牌名称、来源程序集、当前描述（包括游戏提供的附魔／苦痛附加文本）、升级、关键字、当前费用、基础动态变量、可选目标。
- 手牌的各目标数值预览：使用游戏的预览计算和独立变量副本，不把 UI 描述中的数值再盲目叠加 Buff。
- 玩家和敌人的状态效果与层数、遗物及消耗状态、药水、充能球、召唤物。
- 敌人当前意图、当前伤害预览、攻击次数，以及最多三个通过固定连接可见的后续动作类型。
- 可选的**当前抽牌堆真实顶部顺序**。可以关闭；关闭后仅发送排序后的牌堆清单。
- 无法读取的字段及预测边界，明确标为未知。

面板底部的「实时战斗预览（尚未发送）」随游戏变化刷新。另一个「最近请求与 AI 原始回复」入口展示上一次实际发送的冻结请求、接口回复、AI 正文及校验结果，可以复制诊断；二者不一定是同一时刻。中文直接显示，不再默认转为 Unicode 转义。联机时只读取本人的手牌和牌堆，不读取队友私有手牌；联机行为尚未实测。

0.2.1 专注本回合，已移除多轮选项和后续轮次输出要求。此前保存的战斗模式选项自动忽略，URL、模型、密钥等配置仍可沿用。AI 需要结合当前状态效果与遗物的描述、层数、使用状态和触发时机，说明对本轮打法有实际影响的机制；读取到描述并不代表隐藏的 Mod 逻辑已被模拟验证。

0.2.0 区分卡牌作用对象与手动目标：游戏确认无需选目标的 Self 卡，AI 填写本人 ID 时可无损归一为 null；其他错误目标仍拒绝。星星费用负数哨兵转为零花费，并单独注明星星 X 费用。

## 预测与 Mod 兼容性

当前抽牌顺序不等于下回合保证抽到的手牌：抽牌、插牌、洗牌、额外效果和 Mod 钩子会改变它。当前敌人意图也可能在玩家行动后改变。

后续动作只沿游戏内置 `MoveState` 的固定连接读取；遇到条件、随机或自定义分支即停止。不会推进敌人状态机、修改行动历史或消耗游戏 RNG，AI 快照采集本身不执行整回合模拟；本地模式在隔离进程中另行模拟。

采用运行时名称、描述、费用、效果与动态变量，能为很多自定义卡牌提供上下文。**这不保证兼容所有 Mod**：隐藏计数器、缺失描述、特殊选择流程、覆写规则或具有副作用的自定义预览钩子仍可能需要单独适配。读取失败时不会把未知值伪装成零；核心状态读取失败时停止提供新建议。

AI 的整套打法没有经过战斗模拟器证明最优。代码会校验 JSON、快照身份、卡牌／目标身份和首步基本可行性；后续依赖关系与战术效果仍是 AI 建议。

## 密钥与数据

- 默认仅在当前游戏进程内保存 API Key。
- 可选 Windows DPAPI 加密保存，绑定当前 Windows 用户，文件在 `user://spire_ai_coach/api-key.dpapi`。
- URL、模型等普通设置位于 `user://spire_ai_coach/config.json`；该 JSON 不含 Key。
- 取消勾选记住密钥并保存，会删除已保存密钥；新 Key 仍可在本次游戏中使用。
- 不记录请求鉴权头或配置的完整接口 URL；HTTP 非成功响应体不读取、不保存；不收集遥测。
- 在 `user://spire_ai_coach/diagnostics/` 保留最近 20 次请求的冻结输入、成功 HTTP 响应体（包括 SSE 事件及校验失败的回复）、拼接后的 AI 正文、耗时、结束原因及具体失败信息。取消、超时和断线也保留已接收到的部分。本次配置的密钥及其 JSON 转义形式会被替换为 `[REDACTED]`；若正文出现跨流式片段的密钥或其末尾前缀，原始事件体会省略，保留脱敏正文。记录包含战斗信息，分享前请检查内容；其他 Mod 自定义文本不保证不含个人信息。
- 提交和安装包都不包含游戏原始程序集、游戏源码、玩家存档、真实 API 凭据或本机路径配置。

## 开发

需要 .NET 9 SDK 和合法安装的游戏。构建不会自动修改游戏目录。

```powershell
# 只验证核心逻辑，不需要游戏文件或 API Key
dotnet run --project tests/SpireAiCoach.Tests -c Release

# 编译与打包，需要游戏引用
./scripts/Build.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\Slay the Spire 2'

# 可选：安装已构建的文件，已有本 Mod 文件会备份
./scripts/Install.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\Slay the Spire 2'
```

也可以设置环境变量 `STS2_GAME_DIR`。非标准数据目录使用 `dotnet build ... -p:GameDataDir=...`。CI 只运行不含游戏依赖的测试，不重新分发游戏 DLL。

## 项目结构

- `src/SpireAiCoach.Core`：冻结快照、提示词、JSON 合同、HTTP 客户端和显示格式。
- `src/SpireAiCoach.Mod`：游戏状态采集、Godot 面板、本地设置与加密密钥。
- `tests/SpireAiCoach.Tests`：可直接运行的回归测试，无额外测试框架依赖。
- `docs/architecture.md`：数据流、输出合同、线程和适配边界。
- `docs/research.md`：相关 Mod 与开发依据。
- `docs/validation.md`：已执行验证和待实测部分。

后续可以在保持只读快照边界的前提下，加入专门的预测适配器、针对真实快照的模型对比、选牌／商店建议和更多 API 协议。
