# 尖塔 AI 教练 · Spire AI Coach

《杀戮尖塔 2》的只读 AI 指导 Mod。配置自己的 API URL、模型和 Key，选择指导本回合或本次战斗（最多 10 轮，含当前轮），获取出牌顺序、目标、理由及后续条件计划。**由玩家自己操作，不自动出牌。**

当前版本：**0.2.0，实验版**。已针对本机 `v0.111.0` 游戏程序集编译；游戏更新后可能需要重新编译或适配。

## 使用

1. 从本仓库 Releases 下载安装包，解压，将其中 `SpireAiCoach` 文件夹放进游戏的 `mods` 目录。
2. 最终结构应为 `Slay the Spire 2/mods/SpireAiCoach/SpireAiCoach.dll` 和同目录 `SpireAiCoach.json`。
3. 重启游戏，在 Mod 列表启用「尖塔 AI 教练」。不依赖 BaseLib，不需要 PCK。
4. 按 **F8** 展开面板，按 **F10** 打开设置，填写 URL、模型、API Key，点击「保存设置」。
5. 进入战斗，选择「指导本回合」或「指导到本次战斗结束」，在自己的出牌阶段点击「开始分析」或按 **F9**。
6. 依次查看建议并手动操作。战斗状态变化时，旧建议会标记过期；遇到新抽牌、选牌或随机结果，可以重新分析。

API 支持 **Chat Completions 兼容协议**。URL 可以填 `https://你的服务商/v1` 或完整的 `/chat/completions` 地址。仅填域名时补上 `/v1/chat/completions`；自定义路径保持原前缀。支持本机 HTTP 服务，例如 `http://localhost:11434/v1`。纯 Anthropic Messages / Gemini 原生接口需要兼容网关，第一版没有其原生适配器。

每次点击产生一次请求；不会后台自动调用、自动重试或设置输出 token 上限。API 费用取决于你配置的服务商。默认超时 120 秒；可在本地配置中将 `timeout_seconds` 改为 10–600 秒。

## 发送给 AI 的信息

- 当前回合、本人行动阶段、层数、进阶等级、生命、格挡、能量和星星。
- 本人的手牌、抽牌堆、弃牌堆、消耗牌堆和正在结算区：每张实例、总数、按卡牌和升级等级统计的数量。
- 卡牌名称、来源程序集、当前描述（包括游戏提供的附魔／苦痛附加文本）、升级、关键字、当前费用、基础动态变量、可选目标。
- 手牌的各目标数值预览：使用游戏的预览计算和独立变量副本，不把 UI 描述中的数值再盲目叠加 Buff。
- 玩家和敌人的状态效果与层数、遗物及消耗状态、药水、充能球、召唤物。
- 敌人当前意图、当前伤害预览、攻击次数，以及最多三个通过固定连接可见的后续动作类型。
- 可选的**当前抽牌堆真实顶部顺序**。可以关闭；关闭后仅发送排序后的牌堆清单。
- 无法读取的字段及预测边界，明确标为未知。

面板底部的「实时战斗预览（尚未发送）」随游戏变化刷新。另一个「最近请求与 AI 原始回复」入口展示上一次实际发送的冻结请求、接口回复、AI 正文及校验结果，可以复制诊断；二者不一定是同一时刻。中文直接显示，不再默认转为 Unicode 转义。联机时只读取本人的手牌和牌堆，不读取队友私有手牌；联机行为尚未实测。

战斗模式仍只调用一次 AI：本轮显示具体操作，后续最多 9 轮逐轮显示策略及成立条件；预计提前结束或无法继续推断时说明原因。它不执行多回合模拟，也不会自动连续调用模型。切换范围、改变战斗状态都会使旧建议失效。

0.2.0 区分卡牌作用对象与手动目标：游戏确认无需选目标的 Self 卡，AI 填写本人 ID 时可无损归一为 null；其他错误目标仍拒绝。星星费用负数哨兵转为零花费，并单独注明星星 X 费用。

## 预测与 Mod 兼容性

当前抽牌顺序不等于下回合保证抽到的手牌：抽牌、插牌、洗牌、额外效果和 Mod 钩子会改变它。当前敌人意图也可能在玩家行动后改变。

后续动作只沿游戏内置 `MoveState` 的固定连接读取；遇到条件、随机或自定义分支即停止。不会推进敌人状态机、修改行动历史或消耗游戏 RNG，也没有执行整回合模拟。

采用运行时名称、描述、费用、效果与动态变量，能为很多自定义卡牌提供上下文。**这不保证兼容所有 Mod**：隐藏计数器、缺失描述、特殊选择流程、覆写规则或具有副作用的自定义预览钩子仍可能需要单独适配。读取失败时不会把未知值伪装成零；核心状态读取失败时停止提供新建议。

AI 的整套打法没有经过战斗模拟器证明最优。代码会校验 JSON、快照身份、卡牌／目标身份和首步基本可行性；后续依赖关系与战术效果仍是 AI 建议。

## 密钥与数据

- 默认仅在当前游戏进程内保存 API Key。
- 可选 Windows DPAPI 加密保存，绑定当前 Windows 用户，文件在 `user://spire_ai_coach/api-key.dpapi`。
- URL、模型等普通设置位于 `user://spire_ai_coach/config.json`；该 JSON 不含 Key。
- 取消勾选记住密钥并保存，会删除已保存密钥；新 Key 仍可在本次游戏中使用。
- 不记录请求鉴权头或配置的完整接口 URL；HTTP 非成功响应体不读取、不保存；不收集遥测。
- 在 `user://spire_ai_coach/diagnostics/` 保留最近 20 次请求的冻结输入、成功 HTTP 响应体（包括校验失败的回复）、AI 正文、耗时、结束原因及具体失败信息。本次配置的密钥及其 JSON 转义形式会被替换为 `[REDACTED]`。记录包含战斗信息，分享前请检查内容；其他 Mod 自定义文本不保证不含个人信息。
- 提交和安装包都不包含游戏原始程序集、游戏源码、玩家存档、真实 API 凭据或本机路径配置。

## 开发

需要 .NET 9 SDK 和合法安装的游戏。构建不会自动修改游戏目录。

```powershell
# 只验证核心逻辑，不需要游戏文件或 API Key
dotnet run --project tests/SpireAiCoach.Tests -c Release

# 编译与打包，需要游戏引用
./scripts/Build.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\Slay the Spire 2'

# 可选：安装已构建的文件，已有本 Mod 文件会备份
./scripts/Install.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\Slay the Spire 2'
```

也可以设置环境变量 `STS2_GAME_DIR`。非标准数据目录使用 `dotnet build ... -p:GameDataDir=...`。CI 只运行不含游戏依赖的测试，不重新分发游戏 DLL。

## 项目结构

- `src/SpireAiCoach.Core`：冻结快照、提示词、JSON 合同、HTTP 客户端和显示格式。
- `src/SpireAiCoach.Mod`：游戏状态采集、Godot 面板、本地设置与加密密钥。
- `tests/SpireAiCoach.Tests`：可直接运行的回归测试，无额外测试框架依赖。
- `docs/architecture.md`：数据流、输出合同、线程和适配边界。
- `docs/research.md`：相关 Mod 与开发依据。
- `docs/validation.md`：已执行验证和待实测部分。

后续可以在保持只读快照边界的前提下，加入专门的预测适配器、针对真实快照的模型对比、选牌／商店建议和更多 API 协议。
