# 尖塔 AI 教练 · Spire AI Coach

《杀戮尖塔 2》的 AI 回合指导与本地战斗规划 Mod。配置自己的 API URL、模型和 Key 获取 AI 建议，或使用本地模拟规划整场战斗。AI 建议由玩家操作；本地路线取得完整逐步记录后可点击“执行方案”自动出牌。

当前版本：**0.7.38，实验版**。已针对本机 `v0.111.0` 游戏程序集编译；游戏更新后可能需要重新编译或适配。


0.7.38 改进回收和生成卡牌的通用选牌排序：按原生伤害/防御预览及支付来源卡后剩余的能量、星星，评价还能打出的后续牌。多个目标和整组牌共享同一份资源预算；观察真实牌堆移动，区分回手、放回抽牌堆和消耗。两种本地算法共用，不按卡牌名字实现效果，不删除候选或缩短搜索预算。保留已安装 0.7.37 的最低损失证明及原分支的分页补交和可达性记录。



0.7.38 在「计算选项 → 可选出牌目标」新增两个独立单选：从当前牌组选一张尽可能多打的牌，以及一张尽量用于补刀的牌，均可选择「不启用」。默认先保住战后生命，同血量时先比较补刀次数，再比较使用次数；同模型的副本、升级版及自动重复打出合并计数。勾选「允许少量损血」后，在净损血严格小于所填值的获胜路线中优先这些目标，例如填 5 允许净损血 0–4；没有符合路线时回到少损血策略。净损血包含战中与战后回血，计数从当前计算状态起。两种算法及继续优化共用并保存设置，结果显示预计次数；启用目标时继续原搜索预算，不触发无伤或最低损失提前返回，关闭目标后恢复原无伤设置。

0.7.37 将提前返回扩展到已经证明的最低净损失：完整覆盖各个可能更好的操作后，找到达到生命损失与用药下界的获胜路线即可停止两种算法的后续搜索。包含原生战中、战后回复；未知回复、未完成选牌页和预算中断均保持未证明。面板显示「达到最低损失即返回」及已确认的最低净损失，旧设置继续生效。默认预算不变，也不按单张卡牌另写效果规则。


0.7.34 修复模拟与实际抽牌不一致：学习出牌收益时不再额外调用 `Hook.ShouldDraw`。某些 Mod 会在该钩子里消耗阻止抽牌的次数，原来的试探会提前用掉次数，导致返回实际无法执行的抽牌路线。现在只观察真实出牌后的结果，抽牌及其限制均由原生命令和 Mod 钩子结算。

0.7.33 自动执行会等原生动作执行器和延迟状态更新全部完成，再核对下一步。预计获胜的路线走完却未结束战斗时明确报告分歧；部分路线不再显示含糊的“已执行完方案”。每次执行保存步骤、停止原因、原生状态与操作历史指纹，以及实际生命、能量、星星、手牌和敌人状态，供诊断提前停止的问题。

0.7.36 修复大选牌列表跨分页重放时遗漏既定组合的问题，避免因此重新启动整组计算。手动并发提前准备所选数量，各路同时准入；预热期间计算可以加入已在准备的实例。自动模式仍按需增加，两种算法的搜索预算不变。

0.7.38 补交重放既定前缀时新发现的分页选牌组合，按完整操作历史在实例内去重，并继续使用原共享队列。结果区分原生模拟获胜、独立复核获胜及是否有解仍未知，显示实际停止原因。预算完成、队列暂空或只有死亡样本都不表示无解；只有完整单根覆盖且没有截断、动作排除和模拟错误时，才报告指定模拟范围内未存在获胜路线。没有扩大预算或按卡牌名称新增规则。

最近未获胜战斗的同场调查仍未找到获胜路线，未穷尽的预算搜索不能当成无解证明；额外死亡评分试验没有改善结果，未发布。固定输入的原生记录与候选／已安装构建的区别见 [验证记录](docs/validation.md)。

0.7.13 优化找到路线后的最终复核：保留真实战斗场景、原生执行器、选牌、规则钩子和逐步状态/历史校验，只在所属后台实例省去字体自动排版、房间淡入淡出及展示/输出调用，改用游戏自带的按需画面资源加载。快速复核异常时只将同一候选改用常规复核，不重新搜索；仍无法通过则不提供可执行方案。搜索预算、路线评分和无伤停止条件不变。

合入新算法后的固定 10 回合 60 步路线，在同一实例预热后按旧/新/新/旧对照，复核请求平均从 **3.96 秒降到 3.60 秒（约 9%）**；每步原生指纹、操作/选牌历史、完整续用点和结算一致。150 项核心检查通过，错误结算仍被拒绝。此前单项改动还覆盖了 7 个原生机制用例。不同批次用时存在波动，不代表所有战斗或 Mod 的提速比例；第一次复核所需的场景资源仍需加载。

0.7.12 新增独立的「新算法整场计算（实验）」按钮，保留原本地整场计算。新算法按完整操作历史组织回合探查与整场试走；两种算法复用同一后台模拟池、数值执行、进度、取消和最终路线复核。每路上限统一为 **64 次整场尝试、60 秒搜索、64 回合**，先达到任一上限即结束；准备与最终复核另计。默认开启的无伤提前返回也适用于两种算法。「继续优化」沿用刚使用的算法；要继续搜索已无伤的路线，先关闭提前返回开关。

新算法在执行前排除已完整评估的操作/选牌历史，不把探查或预算中断当作完成，也不合并血量相同的不同状态。多路按实际合法操作与选择分工，共有的前几步仍需在各自实例重放。0.7.12 的历史验证完成 63 条不同终局、没有重复，取得 8 回合、战后 87/87、无主动用药路线，58 步通过一次常规复核；该批尚未取得六回合路线。最新结果及全局最优的限制见 [新算法设计与验证](docs/turn-search-experiment.md)。

0.7.11 修正回合末手牌扣血的排序提示：根据游戏原生触发标志区分出牌代价和留在手里的风险，仍由原生结算评价路线；没有为单张卡复制效果。补打卡牌导致选牌列表变化时，搜索可重新提议相同模型的唯一合法选项以延续组合，并记录新的选择；最终复核和实际执行继续使用完整状态及选择身份。

0.7.10 在后台数值搜索中跳过音效调用、剩余特效入口、普通日志输出和完整重放文件写入；内存里的操作记录、选牌记录、规则钩子和停止录制收尾继续执行。过程中进度每 100ms、候选每 250ms 最多更新一次，结束和失败立即写出。默认保留 0.7.9 的无伤提前停止功能。

「耗时分析」新增方法累计：显示完整状态复制、序列化、原生校验、指纹核对、卡牌数值重算与输出入口的调用次数、累计用时、最长单次和跳过次数。数据在内存中累计，不逐调用写文件；嵌套方法耗时不能相加。固定 60 步路线在同一热实例中核对了所有动作、选牌、指纹和结算，最终常规执行复核 60/60 通过。这批输出开销被确实跳过，但本次少量样本的总用时有波动，没有证明稳定的整体提速；完整状态复制是下一步重点。

0.7.9 新增默认开启、自动保存的「无伤通关后立即返回（含回血）」：任一路找到获胜且战后生命不低于计算起点的路线，就停止其他搜索，完成一次路线复核后返回。停止条件不再等待额外奖励机制的判断，也不受「继续优化」入口覆盖；关闭开关后可继续原预算搜索。药水仍按现有允许使用选项参与模拟，已允许的用药无伤路线同样可以触发返回。暂不为额外收益继续搜索。

0.7.8 默认使用连续的数值结算队列：后台出牌、敌方行动与状态重算在所属线程按序执行，已有逻辑可继续时立即处理，省去逐帧轮询。卡牌、敌人、选牌、遗物和 Mod 仍运行原来的规则代码；最终选中路线保留一次常规场景复核。搜索预算、分支和评分保持原值。

相同输入与 Mod 的固定路线对照：6 回合 49 步热执行由 2.023 秒降至 0.845 秒，10 回合 60 步由 2.212 秒降至 1.202 秒，每步状态及结算一致。后者仅在起点恢复时等待 3 帧，出牌和敌方回合没有帧等待。这些数据不含首次准备和最终复核，也不代表已解决最优路线的搜索；详情见 [数值执行对照](docs/numerical-execution-experiment.md)。

0.7.7 后台搜索直接初始化原生战斗模型，省去每条路线的冒险和战斗画面、卡牌节点、特效及选牌页面。出牌、敌方行动、抽牌、消耗、升级、选择同步、死亡和战后回血仍调用游戏与已加载 Mod 的实际逻辑；不按卡名重写效果，不改搜索分支或评分。最终采用的路线才回到常规执行中独立复核。遇到依赖画面节点的 Mod 或结果不一致，会重新走常规执行并记录原因，保留原搜索预算和操作集合。

同一冻结战斗的热实例对照，均为 4 路、60 秒预算、每路最多 32 条：常规执行评估 69 条、总等待 65.777 秒；省去场景后完成 128 条、总等待 37.324 秒。后者先到达原有路线数量上限，没有缩短时间预算。动态搜索的路线不同；严格速度比较使用固定路线，并核对每步原生状态、历史和结算。首次引擎与 Mod 启动仍有成本，完整数据和限制见 [性能分析](docs/local-simulation-performance.md)。

后台启动也省去主菜单。单路冷启动的正反顺序对照，平均开始模拟由 44.10 秒提前到 33.21 秒；含最终复核的总等待由 54.02 秒降至 48.83 秒，部分资源延后加载，未把提前开算的全部时间当作净收益。计算实例仍提前准备并保持复用，界面显示真实准备、搜索与复核耗时。

0.7.6 修复后台特效遗留与能力牌飞行路径越界，等待原生动作执行真正完成后立即继续，减少多余帧等待。计算实例提前在本次冒险开始后准备，并随游戏保持可复用，关闭所属游戏后退出。搜索仍保留 60 秒预算，场景恢复、原生效果和最终复核均继续执行。

搜索加入连贯试走和原生效果观察：在当前冻结输入的试走中记录回能、补牌、升级、移除状态牌和获得增益，为后续探索提供提示；每条建议仍以完整原生结算为准。原生弃牌/消耗选择优先尝试状态和诅咒，壁垒等原生钩子阻止清甲时保留多余格挡的探索价值。改变当前动作后不再提前丢掉后续回合的计划。这些规则不按卡名适配，也不删除未知机制分支。

0.7.5 在多路搜索之间分配公共分支任务：合并重复提交的操作/选牌提案，各路领取不同任务再用原生游戏执行；探索与路线改进各保留容量，避免探索队列挤掉后来更好方案的调整。单路继续使用原操作树，搜索预算仍为 60 秒。时间轴新增“分配搜索分支”，结果显示领取任务和重复提交数；这些计数不代表省掉了多少次原生出牌。

公共前缀的**状态检查点尚未实现**。原生存档作为中途检查点的隔离实验未能恢复出牌后的完整状态，被原有校验拒绝，因此每条路线仍要恢复战斗并重放公共前缀。共享提案不等于共享完整状态，也不能据此保证整体更快或兼容所有 Mod；对照与边界见 [性能分析](docs/local-simulation-performance.md)。

0.7.3 按**战后净生命损失**选路，包含战中及原生胜利钩子的回血；累计扣血只是过程诊断，已经补回来的卖血不再被惩罚。同等净损失优先保留药水，先计算不喝药的路线，再交错探索必要用药；开启药水选项不代表必须喝药。净损失为 0 且不用药的获胜方案会明确显示已达到这两个目标，其他收益和最短路线仍不保证最优。

路线改进现在比较额外出牌、删牌、换牌和改变原生选牌目标，完整试走后续战斗；没有壁垒、全身撞击、压缩或状态牌的专属效果镜像。已有获胜路线可作为“继续优化”的起点，仍要重新执行与复核。两种入口均保留 **60 秒搜索预算**，不通过缩短预算宣称提速。

0.7.4 在后台省去移牌、卡牌飞行和拖尾的画面等待，保留牌堆通知、完成信号及节点清理；出牌直接等待原生动作队列完成，减少额外帧等待。卡牌效果、敌方行动、选牌和战后回血仍由原生逻辑执行，前台画面与执行行为保持正常。并发搜索先汇总候选，只为最终要采用的路线独立重放并核对每步状态、历史及结算；复核失败则弃用该候选，再检验其他候选。场景和战斗模型仍需恢复。性能证据及边界见 [验证记录](docs/validation.md)，后续底层方向见 [模拟性能分析](docs/local-simulation-performance.md)。

“展开 / 收起耗时分析”显示从点击到结果就绪的同一时间轴：等待提前准备、共享资源与配置、引擎启动、恢复起点、决策、出牌与敌方行动、最终复核及界面接收。每次成功计算保存 `user://spire_ai_coach/diagnostics/local-timing-latest.json`，不包含 Replay、API 密钥或请求正文。并行阶段的累计用时不能相加当作总等待；动作耗时包含原生结算等待，不代表纯 CPU 时间。详细记录有容量上限，超限会明确显示省略数量。

0.7.2 把默认战斗上限从 10 回合提高到 **64 回合**。选牌按游戏原生流程搜索，支持手牌单选/多选、升级选择、牌堆取牌和生成卡牌选择；弃牌、消耗、升级、抽牌及遗物效果仍由游戏与已加载 Mod 执行，不为每张卡手写效果。已经完成的选择从完整原生记录恢复，不再因为历史里有多选或消耗选择而禁止继续计算。自定义选择页面和未被原生重放记录覆盖的 Mod 状态仍有兼容边界。

牌序搜索增加通用路线调整：把同一回合后出的牌移到前面，在隔离进程实际执行并比较后续结算；按原生卡牌实例重新定位，不能沿用变化前的手牌位置。不同进程共享候选路线与分支提案作为探索起点，调整后的路线必须重新模拟和复核。已移除武装＋专属的优先级规则，未知 Mod 卡也能参与牌序比较；这仍是预算内搜索，不保证全局最优。

后台等待公共资源加载完成，并在一次搜索中保留资源、减少各路线重复预加载；场景与战斗对象仍按路线独立恢复。模拟过程中关闭后台进程自身的战斗存档写入，避免死亡结算删除反复恢复的备份。前台游戏和操作系统句柄隔离边界保持不变。

0.7.0 新增“执行方案”和“停止执行 · Esc”。仅点击后执行已验证的本地路线，逐步核对同场战斗、Mod、原生状态与操作历史；状态偏离、额外选择超时或战斗结束时停止。不自动执行 AI 回复，不领取战后奖励或选择地图。药水使用受计算时和当前开关共同约束。停止后已出手的动作继续正常结算，后续步骤不再执行。

进入单人战斗后会提前准备计算，资源准备和启动同时进行，多次计算复用已就绪的实例。首次加载游戏/Mod 仍需要时间；进度提示改为“准备计算”“正在计算”，具体试走过程可展开查看。

## 本地整场计算

0.6.2 增加战术优先探索、分阶段耗时和路线续用。当前探索优先级依据目标生命/格挡、攻击意图、防御缺口、剩余可用手牌、增伤/易伤/回能预览计算；它不是效果证明，不删除未知或低优先级动作。四分之一的首次探索忽略这个优先级，已执行分支仍由模拟结果反馈选路。普通武装的升级选择已在 0.7.2 接入通用手牌选择流程。

完整复核的路线保存逐步原生状态、生命及操作历史指纹。手动按建议操作后，即使界面漏过中间几帧，只要仍在同一战斗、Mod 集合未变、历史与下一步状态同时一致，就继续显示剩余步骤，无需重新搜索；剩余净损失改用这个续用点的实际生命作为起点，累计扣血也减去已发生部分。动画/敌方回合暂停建议，偏离、未知历史、药水开关变化或无对应操作的状态变化都使路线失效。自动执行则必须逐步匹配，不允许跳过未授权的中间动作。

和 AI 指导共用一个安装包、F8 面板与状态过期检查。点击「本地整场计算（实验）」即可使用，不需要 URL、模型、Key，也不会调用 AI。结果可用后点击「执行方案」执行，或自己按建议操作。F9 仍调用原来的 AI 本回合指导；原有设置保留。

后台在游戏安装目录的同级 `.spire-ai-coach-workers` 中建立独立启动目录。EXE、PCK 和游戏运行库使用同盘 NTFS 硬链接共享，不再复制完整游戏资源；Mod 文件、APPDATA、存档及日志保持独立。删除后台链接不删除原始资源，但共享文件不是写隔离沙箱，后台代码不得修改游戏二进制。准备失败时明确报错，不悄悄退回全量复制。安装脚本会清理旧版带所有权标记且未占用的资源副本，保留诊断。

面板「并发上限」设为 `0` 时，根据逻辑处理器数和可用内存选择不超过 8 路，预留约 3 GB、每个新增实例按约 1.5 GB 估算；手动设置 1–16 路时尊重该上限，不再使用此资源估算缩容。实际数量由待办任务、启动状态和停止条件决定，不一次性启动到上限。点击「保存本地设置」同时保存并发、尝试次数、最大回合、搜索秒数及本地选项，不需要先配置 AI。无界面仍需运行独立游戏/Mod 堆，并发增加会消耗内存和 CPU。启动后的进程和已加载资源随本次游戏复用，不再因闲置十分钟而在下一场重新启动；游戏退出后清理。单独运行的实验实例仍保留十分钟闲置退出。

**后台静音**：独立用户目录在启动前关闭主音量、音乐、音效和环境音，工作进程中同时静音原生 FMOD 与 Godot 总线；Godot 使用 Dummy 音频驱动。不会修改前台游戏音量。

**药水开关**：「必要时考虑药水（优先保留）」默认关闭。开启后先试不喝药的路线，再交错比较可用药水的路线；两类使用独立操作树，避免无药分支闭合导致遗漏用药选择。同等战后净损失先比较喝药数量，再比较战后生命、永久收益和回合数；因此不喝药已经净损失 0 时，不会为了回血超过起点而喝药。关闭仅限制未来主动喝药，自动触发的仙灵药水等仍按游戏机制结算，已经喝过的药水也会在恢复历史时重放。标准原生选牌流程已接入，自定义页面仍有适配限制。开关可随并发一起保存。

**实时进度**：计算时自动展开后台进度，显示各进程当前路线、已评估/获胜数量；下拉选择进程可查看模拟回合、生命条、格挡、能量、手牌、状态效果、敌人属性及当前行动节点。最近 12 步按实际结算显示出牌/药水/结束回合及数值变化。预算条表示时间预算使用量，**不是穷举完成率**。这些是正在试走的分支，不是最终建议；完成时自动收起，可重新展开查看，取消或真实状态变化会清空过期过程。

每条路线从当前操作点连续模拟到战斗胜负，默认最多 **64 个玩家回合（含当前轮）**。每进程默认最多 64 次尝试、搜索预算 60 秒，尝试次数、回合和秒数可在面板配置；每轮最多 24 次出牌/药水操作，另有启动和最佳路线复核时间。新算法的尝试也包含回合探查，因此尝试次数不等于完整胜负路线数。提高回合上限不代表必须模拟到上限，战斗结束即停止该路线，时间和操作预算仍生效。使用原生抽牌、敌方行动及胜利结算，按回合列出具体步骤；胜利方案优先于未完成方案，同等生命和收益时优先更早结束。没有找到胜利时明确显示部分路线和轮数/时间/操作上限，不冒充打通整场。建议中的手牌位置指执行该步骤时的位置；同名敌人同时显示目标编号。按建议出牌后，历史与预测状态一致时自动续用剩余路线；偏离后清除建议，再重新计算。

**算法**：搜索使用结算反馈的操作树，结束回合与出牌共同参与选择，不用“攻击 → 能力 → 技能”的固定排序。不同顺序先获得探索机会，再根据实际試走结果增加好分支的搜索机会；未执行动作不继承其他路线的收益。按完整胜利、战后净损失、主动药水数量及其他收益比较；额外补牌、删牌、换序和选牌调整都执行完整后续战斗。每条路线只恢复一次，两类药水策略各最多保留 8192 个树节点；完整模拟过的相同终止历史不重复执行，时间截断不当作失败回传。不会仅因同名、零伤害或格挡已够而删除操作，也不用不含 Mod 私有状态的同步哈希合并局面。**这是预算内候选方案，不是全局最优。**

后台读取原生战前重放记录，核对模型表、游戏/Mod 程序集及根状态，再模拟合法手牌与目标；正常完成后重新恢复并执行最佳路线，复核每步指纹和最终生命、敌人生命、金币、胜负。前台游戏不参与模拟出牌；继续操作或点击取消会停止本次任务。

当前只支持单人；支持原生生成选择、手牌选择、升级选择、普通列表及战斗牌堆选择。多选组合依据原生最少/最多数量枚举，每次选择最多展开 64 个组合，仍受路线预算限制。使用这些标准流程的 Mod 卡无需按卡名另写选牌适配；自定义页面可能中止该组搜索。若没有完成复核的结果且预算仍有余量，会用新进程补充搜索，暂时排除本次无法完成的卡牌/药水主动操作，并显示其名称；结束回合失败不做这种排除。已经发生的历史动作始终照常重放。补充搜索仍不能完成时返回实际错误，不假装完成整场。Mod 用户档中的额外配置、任意私有/静态字段未被通用复制；相同指纹不证明这些字段完全一致。已启用的 Mod 会复制进后台，但不承诺所有 Mod 都能运行或恢复。错误/状态不一致时不发布该进程的结果，可以切回 AI。

奖励/成长机制的通用识别尚未实现。按用户后续要求，无伤提前返回开关只判断完整胜利与战后净损失，不等待奖励覆盖；关闭后继续按预算搜索。实际停止条件见 [搜索规则](docs/local-search-policy.md)。

## 使用

1. 从本仓库 Releases 下载安装包，解压，将其中 `SpireAiCoach` 文件夹放进游戏的 `mods` 目录。
2. 最终结构应为 `Slay the Spire 2/mods/SpireAiCoach/SpireAiCoach.dll` 和同目录 `SpireAiCoach.json`。
3. 重启游戏，在 Mod 列表启用「尖塔 AI 教练」。不依赖 BaseLib，不需要 PCK。
4. 按 **F8** 展开面板，按 **F10** 打开设置，填写 URL、模型、API Key，点击「保存设置」。
5. 进入战斗，在自己的出牌阶段点击「AI 分析」或按 **F9**；也可以点击「本地整场计算（实验）」或「新算法整场计算（实验）」。本地按钮不需要 API 配置。
6. AI 正文会边接收边显示，接收期间标注尚未完成；完整回复通过校验后，自动整理为带卡牌名称和目标的出牌建议。再依次查看并手动操作。战斗状态变化时，旧建议会标记过期；遇到新抽牌、选牌或随机结果，可以重新分析。

API 支持 **Chat Completions 兼容协议**。URL 可以填 `https://你的服务商/v1` 或完整的 `/chat/completions` 地址。仅填域名时补上 `/v1/chat/completions`；自定义路径保持原前缀。支持本机 HTTP 服务，例如 `http://localhost:11434/v1`。纯 Anthropic Messages / Gemini 原生接口需要兼容网关，第一版没有其原生适配器。

每次点击 AI 分析产生一次请求；不会后台自动调用、自动重试或设置输出 token 上限。API 费用取决于你配置的服务商。默认超时 120 秒；可在本地配置中将 `timeout_seconds` 改为 10–600 秒。

默认使用 `stream=true`，支持 Chat Completions 的 SSE 流。取消、出牌导致状态变化、超时或断线都会停止本次接收，部分内容不会变成正式建议。若服务商忽略流式参数并一次性返回 JSON，会兼容读取这一次回复并在完成时注明，不再发起第二次请求。

固定游戏规则、指导职责和输出合同只放在稳定的首条 system 消息；实时战斗任务与快照放在之后的 user 消息。0.3.1 补齐默认能量刷新、抽牌弃牌、保留／虚无、格挡与伤害触发顺序，并明确“没有副作用的有益动作优先于浪费即将失效的能量”，同时保留反伤、能量保留等合理例外。

完成时显示输入、缓存命中和输出 token 数。默认请求 `stream_options.include_usage=true`；不兼容的接口可在设置中取消「请求流式用量统计」。未返回计数显示未知／未返回，不当作零。缓存命中依赖服务商、模型、相同前缀和缓存有效期等条件；固定 system 为缓存创造条件，但不保证命中或具体优惠。参见 [OpenAI 官方缓存说明](https://developers.openai.com/api/docs/guides/prompt-caching)。不向第三方接口强加专属缓存参数，也不靠补无用文本凑缓存长度。

0.3.2 将消息顺序调整为「固定规则 → 角色与遗物 → 当前战斗状态」。角色与遗物以单独 user 消息放在回合、指纹和手牌等变化字段之前，动态快照中不重复发送。每次仍从同一份最新快照构造全部消息；遗物描述、计数或使用状态变化时同步更新，不为缓存冻结旧值。缓存可以覆盖 user 消息里的相同前缀，不需要把战斗数据提升成 system 指令；后续请求仍发送完整必要信息，不依赖服务商记住上一场战斗。

诊断面板直接展示解开日志和 HTTP 外层 JSON 后的 system / user 消息内容，避免原始诊断嵌套字符串产生大量反斜杠。复制完整诊断和本地文件仍保留原始传输证据。HTTP 包装所需的转义会由接口解析，不是模型额外读取的提示词字符；消息内部 JSON 文本中的引号、描述换行等必要转义仍保留，不能通过直接删除反斜杠压缩。

## 发送给 AI 的信息

- 当前回合、本人行动阶段、层数、进阶等级、生命、格挡、能量和星星。
- 本人的手牌、抽牌堆、弃牌堆、消耗牌堆和正在结算区：每张实例、总数、按卡牌和升级等级统计的数量。
- 卡牌名称、来源程序集、当前描述（包括游戏提供的附魔／苦痛附加文本）、升级、关键字、当前费用、基础动态变量、可选目标。
- 手牌的各目标数值预览：使用游戏的预览计算和独立变量副本，不把 UI 描述中的数值再盲目叠加 Buff。
- 玩家和敌人的状态效果与层数、遗物及消耗状态、药水、充能球、召唤物。
- 敌人当前意图、当前伤害预览、攻击次数，以及最多三个通过固定连接可见的后续动作类型。
- 可选的**当前抽牌堆真实顶部顺序**。可以关闭；关闭后仅发送排序后的牌堆清单。
- 无法读取的字段及预测边界，明确标为未知。

面板底部的「实时战斗预览（尚未发送）」随游戏变化刷新。另一个「最近请求与 AI 原始回复」入口展示上一次实际发送的冻结请求、接口回复、AI 正文及校验结果，可以复制诊断；二者不一定是同一时刻。中文直接显示，不再默认转为 Unicode 转义。联机时只读取本人的手牌和牌堆，不读取队友私有手牌；联机行为尚未实测。

0.2.1 专注本回合，已移除多轮选项和后续轮次输出要求。此前保存的战斗模式选项自动忽略，URL、模型、密钥等配置仍可沿用。AI 需要结合当前状态效果与遗物的描述、层数、使用状态和触发时机，说明对本轮打法有实际影响的机制；读取到描述并不代表隐藏的 Mod 逻辑已被模拟验证。

0.2.0 区分卡牌作用对象与手动目标：游戏确认无需选目标的 Self 卡，AI 填写本人 ID 时可无损归一为 null；其他错误目标仍拒绝。星星费用负数哨兵转为零花费，并单独注明星星 X 费用。

## 预测与 Mod 兼容性

当前抽牌顺序不等于下回合保证抽到的手牌：抽牌、插牌、洗牌、额外效果和 Mod 钩子会改变它。当前敌人意图也可能在玩家行动后改变。

后续动作只沿游戏内置 `MoveState` 的固定连接读取；遇到条件、随机或自定义分支即停止。不会推进敌人状态机、修改行动历史或消耗游戏 RNG，AI 快照采集本身不执行整回合模拟；本地模式在隔离进程中另行模拟。

采用运行时名称、描述、费用、效果与动态变量，能为很多自定义卡牌提供上下文。**这不保证兼容所有 Mod**：隐藏计数器、缺失描述、特殊选择流程、覆写规则或具有副作用的自定义预览钩子仍可能需要单独适配。读取失败时不会把未知值伪装成零；核心状态读取失败时停止提供新建议。

AI 的整套打法没有经过战斗模拟器证明最优。代码会校验 JSON、快照身份、卡牌／目标身份和首步基本可行性；后续依赖关系与战术效果仍是 AI 建议。

## 密钥与数据

- 默认仅在当前游戏进程内保存 API Key。
- 可选 Windows DPAPI 加密保存，绑定当前 Windows 用户，文件在 `user://spire_ai_coach/api-key.dpapi`。
- URL、模型等普通设置位于 `user://spire_ai_coach/config.json`；该 JSON 不含 Key。
- 取消勾选记住密钥并保存，会删除已保存密钥；新 Key 仍可在本次游戏中使用。
- 不记录请求鉴权头或配置的完整接口 URL；HTTP 非成功响应体不读取、不保存；不收集遥测。
- 在 `user://spire_ai_coach/diagnostics/` 保留最近 20 次请求的冻结输入、成功 HTTP 响应体（包括 SSE 事件及校验失败的回复）、拼接后的 AI 正文、耗时、结束原因及具体失败信息。取消、超时和断线也保留已接收到的部分。本次配置的密钥及其 JSON 转义形式会被替换为 `[REDACTED]`；若正文出现跨流式片段的密钥或其末尾前缀，原始事件体会省略，保留脱敏正文。记录包含战斗信息，分享前请检查内容；其他 Mod 自定义文本不保证不含个人信息。
- 提交和安装包都不包含游戏原始程序集、游戏源码、玩家存档、真实 API 凭据或本机路径配置。

## 开发

需要 .NET 9 SDK 和合法安装的游戏。构建不会自动修改游戏目录。

```powershell
# 只验证核心逻辑，不需要游戏文件或 API Key
dotnet run --project tests/SpireAiCoach.Tests -c Release

# 编译与打包，需要游戏引用
./scripts/Build.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\Slay the Spire 2'

# 可选：安装已构建的文件，已有本 Mod 文件会备份
./scripts/Install.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\Slay the Spire 2'
```

也可以设置环境变量 `STS2_GAME_DIR`。非标准数据目录使用 `dotnet build ... -p:GameDataDir=...`。CI 只运行不含游戏依赖的测试，不重新分发游戏 DLL。

## 项目结构

- `src/SpireAiCoach.Core`：冻结快照、提示词、JSON 合同、HTTP 客户端和显示格式。
- `src/SpireAiCoach.Mod`：游戏状态采集、Godot 面板、本地设置与加密密钥。
- `tests/SpireAiCoach.Tests`：可直接运行的回归测试，无额外测试框架依赖。
- `docs/architecture.md`：数据流、输出合同、线程和适配边界。
- `docs/research.md`：相关 Mod 与开发依据。
- `docs/validation.md`：已执行验证和待实测部分。

后续可以在保持只读快照边界的前提下，加入专门的预测适配器、针对真实快照的模型对比、选牌／商店建议和更多 API 协议。
