# 尖塔 AI 教练 · Spire AI Coach

[English](README.en.md) · [下载](https://github.com/w7lau/spire-ai-coach/releases/latest) · [反馈问题](https://github.com/w7lau/spire-ai-coach/issues) · [参与优化](CONTRIBUTING.md)

《杀戮尖塔 2》的战斗指导 Mod，提供 **AI 当前回合建议**、**无需 API 的本地整场战斗规划**和**点击执行本地方案**。用于娱乐、研究与比较打法，不承诺预算内候选就是全局最优解。

设计目标是**尽力兼容不同 Mod**：从游戏底层读取状态，尽量直接调用游戏原生规则与已加载的 Mod 钩子，按照真实玩法模拟出牌、选择与结算，减少逐张卡、逐件遗物手写效果。后台省略已识别的展示与动画等待。这是兼容方向，尚不能保证所有 Mod 都能运行。

## 使用

1. 下载发布包，将 `SpireAiCoach` 文件夹放进游戏目录的 `mods` 文件夹；启动游戏并启用 Mod。创意工坊订阅版与手动版二选一，避免重复加载。
2. 按 **F8** 打开或收起面板。默认隐藏左上角入口，进入战斗也不会自动展开；需要入口时在展开的计算选项中勾选“显示左上角入口”。
3. 在自己的出牌阶段点击“整战探索”或“回合探索”，等待完整路线后手动出牌，或点击“执行方案”。**Esc 仅在执行方案时停止执行**。
4. 使用 AI 时，展开“AI 指导与设置”，填写兼容 Chat Completions 的 URL、模型名与 API Key，保存后点击“AI 分析”。F9、F10 不再绑定操作。

当前发布主要验证 **Windows x64、游戏 v0.111.0**。游戏更新和第三方 Mod 可能改变接口或引入后台无法处理的效果；遇到问题请报告实际游戏、Mod 与教练版本。游戏界面目前主要为中文。

## 两种本地搜索

| 名称 | 探索方式 | 共同目标 |
| --- | --- | --- |
| **整战探索 / Battle Search** | 以完整战斗路线展开候选，并根据已有结果调整动作探索顺序 | 从当前状态规划到战斗获胜 |
| **回合探索 / Turn Search** | 按回合组织候选，向后续回合扩展并分发任务 | 从当前状态规划到战斗获胜，不只计算当前回合 |

两者共用原生模拟，包含伤害、格挡、抽牌、弃牌、消耗、选牌、能力、遗物及敌方行动。使用原规则减少逐卡适配，但依赖界面、外部服务或自定义选择流程的 Mod 仍可能需要额外处理。

- 按**战后净生命损失**比较获胜路线，包含战中与战后回血；同等损失优先保留药水。“必要时考虑药水”默认关闭，开启也不代表必须喝药。
- “达到最低损失即返回”在无伤或有充分证据证明已达损失下界时停止；无法证明下界时继续搜索。“找到获胜路线即返回”适合最终 Boss。
- 可设置并发上限、每路尝试次数、搜索秒数和最大回合数。默认每路 64 次尝试、60 秒、最多 64 回合；0 路为自动估算，手动上限 16 路。准备与可选最终复核的时间另计。
- 可指定尽可能多打某张牌、用某张牌补刀，以及可接受的净损血范围；补刀只统计游戏允许触发 Fatal 收益的有效目标，尊重爪牙和 Mod 限制。
- 可查看搜索进度、路线和耗时分解，继续优化已有候选。默认跳过最终复核；可在选项中开启独立复核。
- 自动执行只在玩家点击后启动，限单人战斗；每步核对战斗状态、动作历史与 Mod 环境，偏离预测就停止。AI 文本不会自动执行。

“获胜路线”“损失最小的已发现候选”和“已证明最低损失”是不同结论。达到时间、次数或回合上限不代表穷举完毕；未完成的路线不会当作已获胜方案返回。

## AI 与数据

AI 指导接收当前手牌、三种牌堆、能量、生命、能力、遗物、药水、敌人属性与可见意图等快照，通过流式回复给出本回合建议。稳定的游戏规则和战斗资料放在请求的前部，以便支持前缀缓存的服务商复用；缓存是否命中由服务商决定。

只有点击“AI 分析”才向所填服务商发送战斗信息，可能产生 API 费用。本地搜索不发送战斗信息到 AI 服务。密钥默认只用于当前会话；勾选记住后使用 Windows 当前账户的 DPAPI 加密保存。不要在 Issue 中上传 API Key、配置、完整存档或未脱敏诊断。

## 欢迎一起优化算法

欢迎提交 Issue 和 PR，目标是：**用更少的实际计算时间，找到更低损失、更接近或可证明最优的完整获胜方案**。状态复用、公共前缀、并发调度、原生模拟开销、启发式排序和有证明依据的剪枝都值得研究。

请保持相同输入、相同预算与相同目标做前后对比，报告准备／搜索／复核用时、有效候选数量和路线质量；不要通过缩短预算、漏掉合法操作或忽略 Mod 效果来制造提速。具体入口与提交要求见 [CONTRIBUTING.md](CONTRIBUTING.md)。

## 开发

需要 .NET 9 SDK；编译 Mod 还需要合法安装的游戏。构建不会自动安装或修改游戏文件。

```powershell
# 核心检查，不需要游戏或 API Key
dotnet run --project tests/SpireAiCoach.Tests -c Release

# 编译并打包
./scripts/Build.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\Slay the Spire 2'

# 游戏退出后安装；备份已有 Mod 文件
./scripts/Install.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\Slay the Spire 2'
```

也可设置 `STS2_GAME_DIR`。源码、构建包和创意工坊内容均不附带游戏程序集、游戏资源或玩家存档。

| 目录 | 内容 |
| --- | --- |
| `src/SpireAiCoach.Core` | 搜索组织、状态合同、AI 客户端与显示格式 |
| `src/SpireAiCoach.Mod` | 游戏状态采集、原生后台模拟、面板与执行器 |
| `tests/SpireAiCoach.Tests` | 不依赖游戏的检查 |
| `experiments/LocalIntegration` | 在拥有的隔离环境中运行原生检查 |
| `docs` | [架构](docs/architecture.md)、[搜索策略](docs/local-search-policy.md)、[性能](docs/local-simulation-performance.md)、[验证记录](docs/validation.md)、[历史更新](docs/CHANGELOG.zh-CN.md) |
| `workshop` | 中英文发布说明与原创封面源文件 |
