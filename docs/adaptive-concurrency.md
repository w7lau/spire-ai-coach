# 按实际任务启动计算实例

0.7.22 修复手动设置仍被资源估算缩容的问题。设置为 8 时允许最多八个进程，两个算法按钮仍先启动一路，再按真实待办任务增加；目标已达成、队列无足够任务或本次搜索开始收尾时可以少于八路。只有设置为 0 的自动模式使用 CPU、可用内存和可复用实例内存估算，自动不超过 8 路，手动上限为 16。0.7.14–0.7.21 的旧实现曾把手动值再次按资源约束缩小。

`LocalWorkerPool.Prepare` 只准备实例 0。计算开始后，`LocalConcurrency.Run` 每次最多增加一路，取消和无伤停止后不再增加，并等待已经启动的请求结束或完成停止清理。实例在游戏会话内继续复用。

## 原算法：共享队列驱动

实例 0 建立根状态后提交合法首步和可选的改进种子。其他实例不重复提交同一批首步。每个实例只生成自己实际取得的最佳候选的改进任务，独立候选仍保留；任务仍由共享队列统一领取。

父进程读取 `LocalSearchWork.Stats` 的待领取数量，扣除尚未准备好的实例已经预留的任务，存在额外任务才增加一路。队列暂空但其他实例还在执行时，等待它们提交新分支；没有活动任务时结束本次队列搜索。不会在队列暂空时退回各自从根状态随机重搜。退出的任务所有者不再计入活动数量，未完成任务不会据此成为已完成路线。

0.7.16 在首个共享搜索实例完成后关闭扩并，避免实例退出释放内存后才补开一个新进程、再跑一整份预算。已经启动的实例正常收尾；无伤停止和取消仍停止它们。固定分区算法仍需启动所有已分配的根分区，不受此关闭规则影响。此规则没有更改每路的搜索预算。

`RecordTerminal` 只登记已完成胜利或死亡的完整动作历史。身份包含原生前状态、回合、卡牌实例或真实手牌位置、目标、药水槽和完整选牌身份；显示名称和排序提示不参与身份。尚未领取且完全一致的任务可以跨任务类别跳过，新提交的相同完整路线也会跳过。预算截断、未结束的回合上限结果、不同选择或不同原生状态保持开放。这仍不保证所有执行轨迹都没有重复：已经同时领取的重叠任务可能收敛到同一路线，公共前缀也仍会重放。

## 新算法：共享后续分支

0.7.18 起默认新算法使用 LocalTurnWork 的内存共享队列。已观察的实际操作和选牌前缀按所有权领取，后续回合新分支也可以交给其他实例；父进程按真实待办任务扩大并发，不限于根动作数。固定前缀内不重复发布祖先兄弟，已领取任务归属与后续完整历史核对不变。

## 关闭共享时的固定分片

新算法的本地回合前沿和完成历史覆盖有固定的所有权约束。第一路报告根状态实际合法动作数量，每一路独立按 `min(本次资源上限, 根动作数)` 计算同一个分片数量，父进程依次启动这些实例。整个请求期间不会改变分片总数，避免后来增加实例夺取已经覆盖的历史或留下未分配的历史。

根状态只有一个动作时只运行一路，该实例仍可探索后续回合的所有分支。根状态动作较多时使用相应数量的分片。按后续前沿再次拆分、转移分片尚未实现。

## 搜索预算与边界

每路默认 64 次尝试、60 秒搜索、64 回合，每回合操作上限保持原值。0.7.22 可保存尝试次数 1–10000、回合 1–1024、搜索秒数 1–3600；两个算法和继续优化共用，达到次数或时间上限即结束，新算法也将回合探查计入尝试。准备计时仍与搜索计时分离；没有通过减少预算宣称提速。最终候选默认进行原生执行复核，保留快速复核和常规复核回退；显式跳过时沿用 0.7.17 起完整首遍记录和逐步执行守卫。

本次没有共享可恢复的中途游戏对象、RNG、Mod 私有字段或战斗状态。公共前缀没有变成一次执行后跨进程复用。隔离验收用于检查真实启动顺序、源战斗保持不变和完整复核；少量样本不是吞吐提升比例、全局最优或任意 Mod 兼容的证明。
