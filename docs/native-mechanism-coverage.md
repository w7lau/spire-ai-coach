# 原生机制与选择覆盖

本清单针对本机 `v0.111.0`，程序集模块 `73b63ee0-6c0a-47bb-b0d1-b21f6d94222e`。只读元数据清点得到 603 个非抽象卡牌模型类、299 个遗物类、283 个能力类、66 个药水类；包含 Mock、废弃及内部模型，不等于玩家可获得的数量。源码、游戏资源和真实存档没有提交到仓库。

本地算法不按卡名复制规则。合法性、目标、支付、伤害、格挡、抽牌、弃牌、消耗、生成、升级、转化、能力、遗物、敌方行动与战后效果继续由游戏和已加载 Mod 的原生代码执行。此次补齐的是算法与这些原生流程之间的选择边界。

| 原生入口 | 后台数据路径及正常执行 | 覆盖范围 |
| --- | --- | --- |
| FromHand / FromHandForDiscard | hand | 过滤后的实际手牌，多选、部分选择及点击顺序；弃牌或消耗的后续效果由调用方执行 |
| FromHandForUpgrade | hand | 原生可升级过滤、自动选择或升级界面 |
| FromCombatPile 两种重载 | pile | 原生牌堆与过滤，数量不足时按原生界面约束处理；不按卡名取牌 |
| FromSimpleGrid / FromSimpleGridForRewards | grid | 原生排序、创建结果、手动或自动确认、允许的空选择 |
| FromChooseACardScreen | offer | 有序卡牌选项与允许跳过，保留原生索引同步 |
| FromChooseABundleScreen | bundle | 整组牌作为一个选项；身份包含组的边界与组内顺序 |
| FromDeckGeneric / FromDeckForRemoval | deck | 原生过滤和排列、牌组实例同步 |
| FromDeckForUpgrade | deck-upgrade | 原生升级资格、原生确认数量 |
| FromDeckForTransformation | deck-transform | 原生变换资格，调用方的预览回调继续执行 |
| FromDeckForEnchantment 三种重载 | deck-enchant | 原生附魔资格、额外过滤、牌组顺序与数量 |

上述 16 个公开命令入口保留原生选择 ID 的分配、开始/结束通知、选择同步、记录及效果。数据路径只替换界面接收器，不设置全局 TestMode，也不覆盖游戏正在使用的 ICardSelector。嵌套出牌或遗物触发的连续选择属于同一动作的有序记录；最终复核、当前状态恢复及实际执行仍校验完整历史。

多选不再永久截取前 64 个组合。LocalSelectionSpace 用精确计数及序号反查表示所有合法组合和顺序，大小之间交错；小空间一次提供全部候选，大空间每次提供下一组 128 个，加入原生提示及精确计划所需选项。128 是候选展开窗口，不是搜索次数或时间预算；重复遇到同一有序选择会继续展开后面的候选。已经指定的合法组合可直接反查，无需先枚举到该位置。

部分展开的选择不会令旧算法搜索树、新算法历史覆盖或差异搜索宣称整棵子树已完成。真实终局可以关闭其精确历史；未展开候选仍保持开放。偏好仅影响尝试顺序，不证明某张牌或某个顺序无用。现有搜索预算、回合上限、药水选项、无伤提前返回及逐步执行守卫沿用配置。

牌组升级、删除、转化、附魔和整组选择在原版主要发生于获得遗物等流程；接上共用接口不表示产品开始自动规划地图、奖励或商店。实际执行入口仍只面向用户指定的单人战斗方案。

使用 `experiments/NativeMechanisms` 可以只读取已安装程序集的模型数量、选牌引用与覆盖缺口。LocalSelectionCoverage 在后台安装选择边界时检查公开命令和网格家族；新增未知入口或接口变化不会被当成已兼容。该检查不是 603 张牌逐张实战证明，也不能识别所有 Mod 私有流程。

第三方 Mod 沿用这些命令和已序列化原生状态时可通过同一入口运行。自定义选择界面、静态变量、独立随机源、未序列化数据或画面节点参与规则仍需额外验证。依赖画面时保留常规执行回退，原生错误不吞掉，状态或历史不一致的路线不发布为可执行路线。没有宣称任意 Mod 全兼容或预算内已证明全局最优。
