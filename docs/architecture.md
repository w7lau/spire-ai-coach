# 设计与合同

## 实验：按回合调度与可证明的生命界限

`SearchOrder=TurnFrontier` 在独立实验入口调度原生操作前缀，探查到下一玩家回合后再调度；完整整场尝试与回合探查单独计数，产品默认排序不变。前置指纹、原生卡牌实例、目标和选择身份必须严格重放；改变选牌后不固定未经重新产生的后续 offer。工作队列不会按可见状态或自身生命合并不同未来。

四路任务调度中的一类工作用于深入刚执行前缀的下一项合法替代操作。连续深入与穿插的宽搜索分开保存，穿插任务不能覆盖正在深入的组合；连续四次深入后接纳另一组提案。每四次试走的整场模拟位置轮换，避免始终只给生命优先队列整场结算反馈。获胜路线的续走提案只占一部分整场尝试，其他尝试按实际新状态继续选牌。每次试走写入 `trial-result`，记录胜负、净损失、用药、回合及探查/预算中断身份，便于区分未搜索到与找到但未选中。

此实验的原生学习额外比较出牌前后仍在手中的同一原生卡牌实例费用，记录真实降费收益；新生成、被移走、已打出的牌以及随当前能量变化的 X 费牌不参与该项观察。此提示只排序，不镜像卡牌效果或删除合法分支，其他排序模式的学习行为保持原样。

生命剪枝基于相同冻结根的已完成获胜结果及可证明的剩余生命增加上界。未知 Mod 回血上界为未知，不能默认为零。已达到零净损失且更少用药的完整路线，可以证明已经或在确切前缀中必将多用药的分支无法改进现有目标。调度评分和重放成本仅排序，不作为删除证明。`LocalTurnSearchStats` 及 `LocalProgress.TurnProbes/BoundPruned` 记录这些不同工作量，最终采用仍由原常规场景完整复核。详见 [实验设计与验证](turn-search-experiment.md)。

## 0.7.8 连续原生数值结算

LocalSearchRequest.NumericalExecution 默认开启，旧请求省略该字段也使用新默认值；内部对照仍可显式关闭。LocalWorkerLogic 只在已检查所有权及可执行路径的后台实例安装，且要求 DataOnlyRun 和当前操作的数值执行上下文。真实玩家操作与最终常规场景复核不进入该上下文。

ActionExecutor 使用原生直接等待动作的分支，同时保留原生 JustBeforeFinished/AfterFinished 事件及暂停选牌时序，不全局开启 NonInteractiveMode。原生卡牌效果、敌方行动、同步选择、RNG、死亡与战后回血代码保持不变。延迟状态通知在队列边界合并后调用原生重算和全部订阅者，只移除帧宿主等待。

原生异步延续在所属线程串行处理，队列和真正决策条件都没有可执行项时，才等待真实引擎事件并记录 logic_frame。原生回合循环捕获的旧上下文仅对完全相同的 CombatState 对象转发到当前队列；不同或已取消战斗回到原调度器。关闭与 Post 共用门锁，避免遗留回调留在已弃用队列。IL 边界不符时撤回本组补丁，保留原执行方式。搜索排序、分支、60 秒预算和最终独立复核要求不变。

## 0.7.7 原生模型执行与常规复核

LocalWorkerDataMode 只在目录所有权标记和独立可执行文件路径核对后安装，使用独立 Harmony owner；任何受检查的原生 IL 边界变化会撤回这一组补丁，继续常规执行。DataOnlyCombat / DataOnlyRun 默认开启，不属于玩家设置；只影响后台搜索 scope。普通玩家进程不安装这些边界，最终 VerifyBest 关闭它们并恢复原生动作入口，重建常规场景后核对每步状态、历史及完整终局。

快速路径省去 NRun、NCombatRoom、卡牌节点、房间/角色画面资产准备、伤害数字、预览、画面震动和选择页面。原生 run/combat model、ActionExecutor、RNG、怪物初始化及全部战斗效果仍保留。GetTweenForCardsChangingPiles 的画面部分由添加/移除完成通知替代；标准选牌在原生 CardSelectCmd 包装内部复用 LocalChoices 的合法分支、身份和计划核对，选择编号及 SyncLocalChoice 不改变。CombatStateTracker 延迟重算保留，只将缺失 NRun 的帧宿主改成 NGame，下一步等待这个原生任务完成。

死亡只替换停止音乐和显示失败页面两个纯画面入口，CreatureCmd.Kill 的死亡防止、死亡钩子、RunManager.OnEnded 和 pending loss / CombatEnded 保留。ForgeCmd 只省 PreviewSovereignBlade，实际锻造及后续钩子保留。没有全局开启 TestMode 或默认开启 NonInteractiveMode，没有卡名效果副本或新增分支删除。

后台默认使用游戏的 StartOnMainMenu=false 入口，模型和 Mod 初始化保留，不创建主菜单；最终常规复核正常准备其画面资产。任一路快速执行失败、unsupported、partial 或最终校验不一致，LocalWorkerPool 先保存实际阶段/动作 trace，再以独立请求 ID 和完整菜单启动重新进行常规执行，使用原预算、原牌组及操作集合。回退原因进入同一时间轴。常规执行本身仍有既有的自定义选择兼容边界；快速路径故障不直接触发卡牌排除。进度中的请求 ID 映射回原请求，序号高于首次搜索及复核，取消及状态过期规则继续生效。

候选没有变化时，result.json 最多每 250ms 重写；候选改变和最终状态立即写入。过程预览仍按原 100ms 上限更新，不跳过原生动作状态核对。资源复用比较 NTFS 的卷及文件 ID：已是同一硬链接则原样保留；仅解除过期目标入口再建立链接，不能用相同大小和时间戳推断文件身份，也不写共享源文件。防止其他计算实例仍映射相同文件时重复删除链接而失败。

## 0.7.5 多路公共分支提案

LocalSearchWork 保存同一请求的公共提案队列，作用域包含请求 ID、快照、原生根指纹、模型表和已加载 Mod。目录由拥有的 worker 根路径推导，不接受请求传入任意共享路径。文件门锁只覆盖提案发布、领取及计数，不持有它执行游戏；每个不可变任务完全写入后才原子发布索引。全部队列访问共用该门锁，不再为每份提案额外创建 IPC 命名互斥锁。

多路搜索提交合法首步、已执行路线上的其他合法动作/原生选牌分支，以及通用路线改进。每条已试路线最多提交 96 个分叉，每个改进种子沿用最多 64 条提案；这是容量限制，不是等价性剪枝，也不表示覆盖全部后续分支。每项同类提案按原生卡牌实例、目标、回合、药水槽和完整选择身份合并，忽略显示名及实例已有时的手牌位置；expand 保留全部前置状态指纹，improve 是允许重新解析的调整计划。两类分别最多保留 512 项，避免探索先填满队列而使后来的改进无处提交。领取在同一锁内写入 owner，同类任务每请求最多领取一次；浅层和深层探索交错，不以低伤害或未知卡牌为删除依据。

各 worker 将已领取的提案在自己的原生世界执行，仍使用本地操作树选择后续动作；树的结算统计不跨进程挪用。其他 worker 的最好结果仍只能作为探索种子。任务可能执行到时间边界，Claimed 不等于 Completed；DuplicateOffers 只表示重复提案提交被合并，不表示实际状态或公共前缀被缓存。最终结果仍需要独立完整复核。所有 lane 与最终复核结束后，池释放本次提案文件，保留小索引计数；清理文件遇到占用不使已验证结果失效。单路及验证命令不启用公共队列。

原生 SerializableRun 不是完整中途战斗检查点：隔离合成宿主出两张防御后保存当前运行，将其作为无历史的新重放根，不能恢复 1 能量、10 格挡的原生状态，被根指纹检查拒绝。该方案未进入产品，未放宽校验、修改源宿主或正式存档。每条路线仍恢复场景并执行公共前缀；这不证明其他完整检查点方案不可行，也不支持用可见状态哈希合并任意 Mod 状态。

## 0.7.4 原生牌堆回调与队列完成等待

LocalWorkerVisuals 在拥有的模拟进程中登记 CardPileCmd.GetTweenForCardsChangingPiles 返回的 Tween，以及手动出牌使用的 AppendPlayPileLerpTween。登记表使用弱引用，并在 Search 的 finally 清空。只在这些 Tween 的原生 AwaitFinished 入口以有界 CustomStep 执行完成回调，保留原始牌堆命令、返回值、移除/添加通知、节点清理及 Tween 回调。未知长/循环 Tween 未完成时沿用原等待，不能假报完成。节点退出条件及已经取消的 token 沿用原生失败/取消语义；不把整个回合末任务设为 CompletedTask，也不全局强制 skipVisuals，因为静默移牌会省略部分通知。

牌堆回调还会创建 NCardFlyVfx / NCardFlyShuffleVfx。仅省 Tween 等待而继续让飞行、拖尾动画逐帧采样，会使快速移动的节点产生过长拖尾补点循环；实际四路测试的主线程调用栈与数组溢出已确认 NCardTrail.CreatePoint 卡点。因此后台同时省去这两个原生 PlayAnim 的曲线/缩放循环：保留 CardAddFinished 通知、SwooshAwayCompletion 完成和原生节点退出清理，并跳过纯 Line2D 拖尾采样。其他 Tween、卡牌 OnPlay、Mod 钩子、敌方行动、回合末状态效果和 CombatEnded 均不替换；没有卡牌名称或 Mod 名称分支。

出牌入队时，原生 EnqueueWithoutSynchronizing 已同步创建 BecameEmpty 的完成任务，因此后台可以直接等待该任务，不必先额外等待一帧。等待期间仍处理 LocalChoices，并等待队列完成或下一帧，防止已完成动作继续空等。药水入队后的帧等待、敌方回合完成条件和 StableOrTerminal 的稳定边界继续保留。

本地协议的 FastCardPresentation / FastNativeWaits 默认开启，只在 SimulationSpeed>1 的 Search scope 生效，用于同构建、同速度的原生对照实验；产品设置不暴露这些内部开关。普通速度及实际玩家进程保持原路径。搜索预算、候选排序和采用前的独立复核要求不变。

## 0.7.3 搜索与复核分离、净生命成本

LocalWorkerPool 首阶段对各 lane 冻结 DeferVerification=true；searched 结果只有候选，不能直接发布给前台。汇总后按 LocalSearchPolicy.Better 选择候选，提交拥有独立请求 ID 的 VerifyCandidate 命令，重新从同一原生根执行完整路线。仅 done 且拥有与 Actions 等长的 Continuation 的结果可发布；复核失败会丢弃此候选，再尝试其他候选，全部失败明确报错。池将验证阶段进度映射回原请求及独立递增序号，不混用旧搜索进度。取消仍只停止拥有的进程。Timing.Verifications 记录完成的独立复核数量，正常请求为 1，不再每路都复核其局部最佳。

每次原生恢复后冻结 StartingHp；NetHpLoss=max(0,StartingHp-Hp)，Hp 是 CombatEnded 之后的原生最终值，包含胜利回血。获胜、生存优先；获胜路线先比净损失，再比主动用药数量、战后 HP、MaxHp、金币、敌人 HP、回合及动作数。HpLost 是过程累计扣血，只作诊断，不惩罚已恢复成本。未完成路线仍先比较敌人剩余生命，不伪装完整胜利。旧记录缺少 StartingHp 时退回战后 HP 比较，不伪造净损失。ContinuationPoint 保存该步生命，续用从该生命重新计算剩余净损失。

开启 IncludePotions 时先建立无药基线，无药与允许用药的操作树独立，各自最大 8192 节点。每三条普通试走中一条允许用药；含用药的完整种子/调整方案也按请求允许用药。候选同等净损失优先少喝，初始净损失 0 的无药胜利不会被用药后额外回血挤掉。未知奖励仍不启用提前停止。

LocalDecision 记录每个动作前的原生合法操作及动作内 LocalChoiceDecision。LocalRouteRefiner 交错提出同轮重排、额外出牌、选牌目标变化、操作替换和删除，最多排队 64 条；不跨边界移动既有结束回合或药水。完整未来计划继续作为种子，无法重新匹配的步骤跳过后回到搜索。旧选择仅在 OfferHash/Kind/模型/Index/Indices 完全相同时作为探索提示，否则重新展开；每个结果重新记录本次真实选择。无需识别壁垒、全身撞击、压缩等卡名。

LocalWorkerVisuals 仅在 TryStart 检查拥有标记及隔离可执行文件之后安装。Search scope 的 SimulationSpeed>1 开启角色动画入口跳过、生成选牌窗口 UI 防误点延迟跳过，以及后台 TimeScale=8、MaxFps=240；finally 关闭 scope 并恢复引擎参数。真实执行不安装这些补丁、不跳过动画或选牌保护。场景恢复和效果仍是原生路径，任意 Mod 基于墙钟、节点回调的行为尚不能由同步指纹证明等价。

搜索预算仍为 60 秒；准备与首个根恢复不扣探索预算，实际总耗时包含它们及最终复核。继续优化只将严格匹配当前战斗/Mod/历史/原生状态的剩余路线作为 InitialPlan，不复制旧分数或省略复核。

## 通用原生选择、牌序改进与战斗范围（0.7.2）

LocalAction.Choices 保存动作内部的有序选择（整组选项 OfferHash、分支索引、模型、显示名、Indices 和 Kind）。LocalChoices 支持 NChooseACardSelectionScreen、NPlayerHand 的 SimpleSelect/UpgradeSelect、NSimpleCardSelectScreen 和 NCombatPileCardSelectScreen。选项按原生过滤器及牌堆顺序取得，手牌/牌堆选择按原生最少/最多数量枚举，最多 64 个组合，按数量交错探索空选/单选/多选，不遍历整个大规模幂集。牌堆页面的 `_cards` 为空，必须读取 `_pile.Cards` 和 `_filter`，并沿用原生不足数量处理。弃牌、消耗、复制、升级和抽牌效果由原生命令及 Mod 执行；SimpleSelect 本身不能被假定为弃牌或消耗。

选择身份包含流程类型、当前战斗指纹、选项原生序列化数据及数量限制。手牌流程以本次 completion source 标识而非重复使用的手牌节点去重；真实执行中的生成页面等待原生 350ms 输入保护，0.7.3 仅后台模拟跳过。调用原生选牌与确认处理器，不接管全局 Selector，不绕开 choice ID、记录或恢复动作钩子。选项变化、次数不符或计划外选择即停。只在隔离模拟或用户点击执行后的单个动作范围内工作，不操作奖励/地图页面。未知自定义页面仍停止该组搜索。

搜索把选择视作当前动作前缀的子分支，只有执行后才获得结算反馈；复核和显式执行消费完整 Choices。History 纳入玩家、choice ID 和完整 NetPlayerChoiceResult 数据，保留 CombatCard、多选、DeckCard、MutableCard 等原生身份。历史恢复期间，LocalReplayChoices 在已验证所有权的 worker 内临时让原生同步器消费记录结果；FromNetData 解码后通过 SyncLocalChoice 保留原生记录、暂停/恢复协议，并核对每个 ID 和完整结果。已完成的历史选择不会重开 UI。scope 结束要求历史队列全部消费并核对当前根指纹；不猜测历史结果。内部仍从原生战前记录重建当前局面，未引入只含可见字段的近似 checkpoint。

LocalRouteRefiner 为候选路线提出同回合牌序调整，不跨药水或回合边界。先测试后出的牌提前，按 CombatCardIndex、模型、目标、回合重新解析当前合法动作，不能使用变化前的手牌索引。旧选择不直接套入新局面，重新展开选择并记录本次真实结果；不可用动作跳过后继续正常搜索。每个候选最多排队 64 条调整线路，和操作树交替试走。其他 worker 的同请求、同快照候选只作为探索种子，不能直接作为本进程的结果发布。InitialPlan 仅为原生测试/搜索的起点，同样必须重新解析并执行；它没有直接进入前台执行器的入口。正式建议必须再次原生复核。

默认 MaxRounds=64，worker 接受 1–128；游戏结束即完成该路线，60 秒/32 路线/单回合 24 操作的其他默认预算保持生效。胜利和生存优先，同等生命、收益和药水数时优先较少回合，再比较操作数。没有完成战斗的路线仍明确显示截止原因。

worker 在启动及战斗预加载前等待 NAssetLoader 完成 Common 异步加载，避免 GameStartupComplete 早于资源就绪的竞争。同一请求只执行一次 run/act 预加载；搜索 scope 内保留 AssetCache 资源，避免延迟 Dispose 与下一条路线重载竞争，场景、模型和状态仍各自恢复。仅 worker 将恢复后的 RunManager.ShouldSave 设为 false，避免模拟死亡/胜利对重复恢复的后台存档备份进行删除，实际玩家进程不安装这些 Harmony patch、不改变存档设置。没有新增运行时依赖，引用游戏自带的 0Harmony。

主动结束回合通过 EndPlayerTurnAction 入队，确保进入原生重放记录。原先直接 PlayerCmd.EndTurn 虽能推进战斗，却可能只产生 ReadyToBeginEnemyTurnAction 等自动事件，导致之后重新计算缺少结束回合。模拟、复核、实机三处使用同一入队方式；不会改写已有历史。

卡住时记录具体动作和等待阶段，退役拥有未完成回调的进程。所有组都没有复核结果且剩余计算预算至少 5 秒时，仅用一个新进程追加一次搜索，按模型 ID 排除已报告失败的卡牌/药水主动动作。此排除是保守适配边界，不是等价性剪枝；结果明确列出未纳入的模型名称，状态为 partial。结束回合不排除，重放历史不受排除影响；复核 done 优先于未复核 partial。补搜耗时扣原搜索剩余预算，冷启动与复核仍可能额外耗时；只补一次，不递归重试。进度序号加独立偏移，避免沿用第一次失败的进度。

参考 CombatSolver 的选择子分支和隔离原则，但没有导入其手写效果镜像、纯状态 Fork 或转置表：我们的同步指纹不覆盖任意 Mod 私有状态，不能据此合并不同操作历史。autoSpire 的选牌与异步动作区分作为参考，执行仍保持每步复核。无外部项目代码复制或运行时依赖。参考链接见本次验证记录。

## 本地原生搜索（0.6.2）

LocalTacticalPreview 只在隔离 worker 读取游戏预览与复制后的 DynamicVars，产生探索提示：预计斩杀/移除威胁、防御缺口、可继续使用的手牌与资源、力量/易伤/虚弱/回能。0.7.2 移除 Armaments+ 的专属升级提示，牌序收益由通用调整后的实际结算比较。不是卡牌类型排序，不按显示名识别机制；读取失败回到中性提示。变量 Cards 可能表示弃牌/消耗/选择数量，不泛化成抽牌收益。提示有误仍由原生执行判定；所有合法动作保留。未试动作有 3/4 概率先从最高提示候选中随机选择，1/4 概率沿原权重探索；已试动作继续使用结算反馈与探索项。

LocalSearchTiming 保留 Restore、Action、Decision、Verification、Startup 的兼容累计统计，正常池请求的 Verifications 为 1。0.7.3 另有 LocalTimeline / LocalTrace：由点击入口设置 QueryPerformanceCounter 共同原点，传给每个进程以及独立验证请求；记录非阻塞测时的真实区间、worker、stage、phase、route、step 和嵌套 depth。父进程记录队列、资源共享、创建进程、等待引擎就绪、IPC 与收取结果，导入实际阻塞本次点击的预热区间。隔离模拟记录起点恢复细项、每步决策和原生结算等待、预览、进度写入、清理、验证。只在 terminal 结果发送完整 trace，不在每次进度更新序列化累计历史。单进程记录上限 16384、父进程 65536，明确记录丢弃数；不能相加嵌套 span 或并行 worker 作为用户等待。界面核对来源及显示阶段再加入同一原点；最近成功测时单独保存，不持久化 Replay 或 AI 请求/密钥。时钟和记录不参与原生状态、决策与 RNG，旧结果没有 Trace 仍可读取。

复核时额外捕获每个待执行动作的 ContinuationPoint：动作位置、BeforeHash、当前历史指纹/计数、此前累计失血及当前生命。历史规范化明确的手动卡牌实例索引/模型/目标、药水槽/目标、结束回合和完整原生选择数据，保留玩家身份与操作顺序；Hook 和回合 readiness 由原生状态复核覆盖，未知动作拒绝。复核根的历史必须与主进程冻结请求一致，不一致则不提供续用点。只有已验证且带续用点的结果进入 LocalContinuation。

前台在同一 CombatId、LoadedMods 及稳定玩家阶段核对完整历史与原生指纹；允许一次向前跳过多个已执行动作，不允许倒退或模糊匹配。观察到快照变化时必须匹配至少一个实际计划动作的进展；无动作、状态改变后又回到同值仍使缓存失效。动画期间保留缓存但清除可执行步骤展示，稳定后才恢复；偏离、战斗退出、取消、新分析、设置保存或药水策略改变清除缓存。复用只裁掉已完成动作并减去已发生失血，不重搜、不执行真实动作。未知 Mod 私有状态仍不因历史/指纹相同而获得通用兼容承诺。

药水由冻结请求 `IncludePotions` 决定，默认 false；LocalAction 的可空 PotionSlot 与手牌动作分开，完整前缀键包含槽位和动作类型。枚举 CombatOnly / AnyTime、未排队、未移除且通过自定义可用性检查的药水，目标用 PotionModel.IsValidTarget（Self 药水显式指向本人，与卡牌不同）。通过 EnqueueManualUse 进入游戏原生使用流程，保留 BeforeUse、IsQueued、消费和后续钩子。被动/自动药水不作为主动操作。关闭开关仍要重放历史 UsePotionAction，否则不能恢复已喝药的真实局面。原生同步结构的药水信息只有模型 ID，附加指纹补入槽位、空槽和排队状态；任意 Mod 私有字段仍不保证覆盖。

LocalProgress 为独立只读 IPC，不作为最终建议合同。各 worker 每 100ms 至多发布一次普通更新，阶段切换强制发布；保留本路线最近 12 步、观察到的前后数值差、当前状态和单调序号。父进程每 250ms 拉取，用请求 ID、快照 ID、worker 序号和更新序号隔离；前台按进程只保留最新待展示帧，Godot 主线程再消费，不排入无界 UI 消息队列。进度可显示失败路线，不据此修改真实游戏。实际状态变化、取消和 AI 模式切换清除过期进度；正常完成保留记录并收起面板。预算条不声称搜索空间覆盖率。

实时展示导致 IPC 更新频率增加；Windows 下 MoveFile 覆盖与并发读取实测会产生 UnauthorizedAccessException，改 File.Replace 又出现短暂 FileNotFoundException。因此 LocalWire 用路径哈希对应的进程间命名互斥锁覆盖一次完整读/写，再作临时文件替换；锁仅覆盖文件操作，不覆盖游戏模拟。进程中止遗留的 abandoned mutex 可接管。高频并发读写测试验证不读取半份 JSON、不因替换竞争失败。

静音只在带所有权标记且可执行文件匹配的后台生效：启动前独立 settings.save 的四种音量为零，传入 --audio-driver Dummy；原生启动结束后及每秒将 NAudioManager（FMOD）、DebugAudio 和 Godot 各总线静音，保留游戏效果与钩子。前台不调用这些设置。audio.json 记录独立设置、Godot mute 状态和实际驱动名称用于验证。

同一面板的本地按钮走独立路径：主线程读取现有 `CombatReplayWriter` 记录及原生状态指纹 → 冻结二进制重放 → 可调数量的私有 Godot 进程 → 原生恢复/历史重放 → 指纹一致后枚举合法手牌、目标及结束回合 → 连续模拟到战斗胜负或预算边界 → 正常搜索完成后重新执行最佳路线、复核结算 → 主线程再次检查快照和原生指纹 → 按回合显示纯文本候选方案。AI Prompt、HTTP、API Key 和 AI 输出合同没有参与此路径。

`LocalCapture` 的私有字段反射只读取游戏已有 `_replay`；版本变化导致字段缺失时明确不可用。只允许单人及空动作队列。worker 核对模型表、已加载 Mod ID/版本/程序集 MVID 和 sts2 MVID，恢复同步器计数，用原生地图入口重进战斗。单人自动执行的钩子/切换敌方回合动作不重复注入；历史手动出牌、药水和结束回合重放，已完成的选择通过原生同步协议恢复。其他未实现动作拒绝，不猜测结果。

每次从战前恢复至当前状态后，按 LocalSearchTree 连续试走，不在每张牌或每个回合重新搭建场景。LocalAction 保存回合、显式 EndTurn、手牌索引、原生 CombatCardIndex、模型 ID、目标 CombatId 与前置指纹，不按名称猜测实例。未启用公共队列时，不同进程的第一次试走分摊首步，后续允许探索全部根动作，避免被较差首步永久限制；0.7.5 多路默认从公共提案领取首步/前缀或改进方案。各自树内使用固定种子探索。攻击、技能、能力没有固定先后。未试分支先获得机会，已有结果的分支用平均收益、最好收益及 UCB 探索项选路，保留继续探索的机会。结束回合和药水始终是合法候选；首次探索权重分别为普通牌的 0.5 / 0.2，不代表收益预测。

树只给实际执行过的路径回传原生结算结果，不再把好路线的分数赋给未执行的替代动作。胜利、未完成、死亡的启发式收益区间分离，结合生命、累计失血、敌人生命、药水和操作代价；它是选路依据，正式最佳方案仍用 LocalSearchPolicy.Better 比较。时间预算截断的路线不回传，避免把机器速度当作战术收益。完成的确切终止操作历史闭合；仅当节点全部合法子分支都闭合时向上闭合，避免重新模拟完全相同的终止路线。各 worker 的统计互不共享。

节点按完整历史分离，不按可见状态哈希合并，不因零伤害或多余格挡直接删牌。树最多保留 8192 个节点，到达容量后继续随机试走而不新增统计；不把容量限制当作剪枝证明。旧 LocalFrontier 仅保留为协议键/回归夹具，不再驱动运行时。默认每进程 32 条路线、每轮 24 次出牌/药水操作、64 个玩家回合、60 秒搜索预算；首轮算一轮。开始动作前检查预算，最后动作结算及最佳路线复核可以超出搜索预算。药水按开关纳入，额外选择展开原生合法子分支，不保证覆盖所有路线或全局最优。

过程扣血通过后台玩家 `CurrentHpChanged` 的正向减少累计，回血不改变这个诊断计数；0.7.3 正式评分改用上述战后净生命成本，累计扣血不再参与排名。胜负等待 CombatEnded 并用 CombatWon 标志确认，不能把最后一只怪归零直接视为所有遗物钩子完成。未完成的后备路线先比较敌人剩余生命，只作有界启发式，不解释为完整胜率。无胜利时显示明确停止原因。收益覆盖未知时不使用无伤提前停止；未来启用也必须先完成胜利、净损失 0 且不耗药，单回合无伤不够。

后台用文件命令/结果和随机请求 ID 通信，每个 worker 独占目录锁；隐藏子进程、独立 APPDATA/LOCALAPPDATA、禁用 Steam。启动目录位于游戏同级 `.spire-ai-coach-workers/<配置指纹>/worker-N`，只读使用的游戏 EXE/PCK/运行库使用同盘 NTFS 硬链接，不再占用每路一套资源空间。每次准备先解除旧链接再建立新链接，绝不覆盖共享文件内容；Mod 目录仍复制以保留各自可写配置。不支持硬链接时明确失败，不隐式全量复制。硬链接不是写保护，后台第三方代码仍可能接触共享文件；此隔离不是通用沙箱。

自动并发保留一半逻辑处理器，按约 1.5 GB/路、预留约 3 GB 内存估算，范围 1–8；可手动设为 1–16。自动估算加回本组件已有 worker 的私有提交量以避免因自身分配而反复缩容，该值只是启发式。减小数量会停止额外 worker。结果记录并发数、总耗时、最慢 worker 搜索耗时及结束时私有提交量（不是纯物理驻留）。共享文件降低磁盘重复，不能消除独立堆、JIT、Mod 初始化及场景开销。

不会复制 AI Key 或玩家存档；重放仅在本机。取消/超时只终止本组件创建的子进程，额外选牌卡住时退役该进程，避免遗留回调跨分支，最多保留此前已结算路线。正常完成后清理战斗并保留进程/资源，闲置十分钟退出。安装脚本只清理带 v1 所有权标记、能获得独占锁且不含链接的旧资源副本，保留诊断和私有数据。

程序集、原生同步/RNG 指纹和可读敌人动作一致是必要校验，不能证明 Mod 的任意静态变量、私有状态、外部配置都一致。运行错误或重放偏差使对应 worker 结果失效；另一 worker 的独立完整结果可标明部分结果后保留。界面沿用请求代次和快照失效机制；执行入口另行检查逐步身份与状态。

## 数据流

Godot 主线程 → `StateCapture` → 独立 C# 快照 → SHA-256 指纹 → `PromptBuilder` → 单次流式 HTTP 请求 → 接收中正文预览 → 完整正文交 `AdviceContract` 投影和校验 → 主线程核对当前指纹 → 纯文本建议。

状态只在主线程读取，网络和 JSON 解析在后台执行。UI 每 750ms 采集一次，发送前、结果显示前另外刷新。游戏 StateTracker 的变更事件递增快照 revision，因此事件后即使可见数值恰好恢复原样，旧建议仍失效。回合、牌堆、资源、意图等变化会取消进行中的分析并标记旧建议。请求序号防止取消后的迟到回复覆盖更新结果。AI 路径只提供建议；本地路线的显式执行见上节。

实例编号由本次战斗内对象身份生成，不发送 Steam ID。牌堆清单保留每张实例；计数按 model_id、名称、升级等级聚合，仅作为摘要，不用于指令身份。玩家名称使用角色名称。自定义效果文本中可能仍含由其他 Mod 插入的文本，发送前可查看完整快照。

## Prompt

`PromptBuilder.SystemPrompt` 是稳定规则：游戏基础机制、例外优先级、证据、不确定性、本回合指导职责。turn-coach-v5 使用三条消息：system、ContextPrompt user、UserPrompt user。ContextPrompt 仅携带 context.player.character / relics；UserPrompt 包含任务、完整快照指纹及去掉这两字段的当前快照。合并两部分即可无损恢复完整观察，遗物不重复发送，原始 CombatSnapshot 与首步校验不变。`AdviceContract.Instructions` 是输出字段与动作枚举的唯一权威，并被系统 Prompt 引用。0.2.1 移除多轮 UI、设置和输出合同，旧配置中的范围字段按未知字段忽略。诊断的 guidance_scope 恒为 current_turn，仅用于记录，不由模型生成。

当前回合推断包括本轮出牌及紧接的敌方行动；要求使用状态效果和遗物的描述、层数、使用状态及触发时机，解释会改变本轮决策的机制。确定性数值结论应核算资源、牌堆移动、格挡和已知触发；缺少后续轮次信息不妨碍规划已有充分证据的本轮动作。该 Prompt 是模型行为要求，没有伪装成本地模拟器校验。

turn-coach-v4 将默认战斗规则集中在 system：回合开始能量重置到上限（不与余量累加）、普通抽5张、抽弃牌循环、消耗／能力牌、保留／虚无、格挡到所属方下回合开始、逐次伤害和前后触发。实际描述和有效规则例外优先。结束回合前比较剩余能量的可行用途：能量本身默认不保值；无已知代价的正收益动作不因收益小而跳过，保留或不出牌则说明实际代价／收益。不会加入“有能量就必须出牌”的硬校验。

针对本机 v0.111.0 已核实的内置机制，固定说明仅对 source=sts2、相应 model_id 生效：覆甲在所属回合结束的早期给予格挡，回合开始再减层；胆小在符合条件且造成穿透伤害的卡牌攻击之后获得格挡。`StateCapture` 读取公开 `SkittishPower.HasGainedBlockThisTurn` 到 used_up；其他状态仍可为 null，不以描述猜测已触发状态。没有修改游戏状态或推进随机数。

SystemPrompt 初始化一次并保留 SHA-256 指纹；不包含动态快照ID、时间、人物或模型。HTTP 两次不同回合测试直接比较前两条消息逐字相同，第三条包含各自快照。ContextPrompt 每次从同一份当前冻结快照重建，没有本地跨请求缓存；遗物含有动态描述、amount、variables、used_up 和 stack_count，任一变化均更新前缀，空数组表示当前无遗物。保留原采集顺序及重复实例，避免压缩改变语义。该指纹可用于诊断规则版本一致性，不是服务端缓存凭据。没有新 reviewer，输出字段、首步校验、纯文本显示和旧建议不再注入的边界保持一致。

选用显式的有序操作序列，因为每一步的资源、目标、条件与后续状态可能变化；不是给模型重复生成所有牌堆。建议不会作为下一次的游戏事实重新注入，下一次始终读取真实状态。

没有第二个模型 reviewer；第一版仅做本地结构、身份和首步校验。不宣称校验器能证明语义正确、后续资源充足或策略最优，不会用自然语言关键词解析模拟玩法。

## 输出字段

模型拥有下表候选输出。消费方为只读 UI；没有写回游戏或存档。

| 字段 | 类型及边界 | 消费与约束 |
| --- | --- | --- |
| snapshot_id | 必填字符串，最长128 | 必须等于输入指纹；显示前再核对当前指纹 |
| summary | 必填非空字符串，最长4000 | 纯文本战术摘要 |
| steps | 必填数组，1–64 | 保留原始顺序，溢出拒绝、不截断 |
| steps[].action | play_card / use_potion / end_turn / reassess | 每种均有消费出口 |
| steps[].card_id | play_card 时必填有效实例字符串 | 属于快照某个牌堆；首步必须在手牌且可打出 |
| steps[].potion_id | use_potion 时必填有效实例字符串 | 来自本人药水；首步检查可用状态 |
| steps[].target_id | 动作需要显式目标时填合法实例；否则 null | 首步符合游戏给出的可选目标；后续只校验存在性 |
| steps[].condition | 必填字符串，最长2000；空为无条件 | 未来抽到的牌／同一实例再次打出必须声明条件 |
| steps[].reason | 必填非空字符串，最长4000 | 玩家可见的简短理由 |
| uncertainties | 必填数组，0–32；每条非空且最长2000 | 不确定性提示，不以此证明规则正确 |

首步检查是当前资源和游戏 `CanPlay` / 目标接口的基本检查。自动触发药水不会建议手动使用；其他 Hook 自定义禁用条件与特殊 Mod 可能需要进一步适配。最后一步必须是 end_turn 或 reassess，这些终止操作之后没有步骤。药水实例不可重复消耗；卡牌实例允许有条件重用以支持回手、循环等机制，条件本身没有被模拟证明。

卡牌 `requires_target_selection` 来自 `!IsValidTarget(null)`，读取失败时为未知。仅当 Self、明确不需选目标、可选目标为空且 AI 指向本人时，等价归一为 null；不修正陌生 ID 或错误敌方目标。`star_cost` 使用游戏花费所用的非负语义（负数哨兵归零），`star_cost_x` 保留 X 星星属性。玩家的 stars 仍表示现有资源。

JSON 顶层和每个步骤先投影到消费字段。额外字段被丢弃；非当前动作拥有的 card_id / potion_id / target_id 规范为空；有效动作使用的必填字段继续严格验证。完整 Markdown JSON 代码围栏可去除，其他语义不唯一的格式不猜测。重复消费键、类型错误、未知 ID、快照不匹配、数组越界均拒绝。

## HTTP 与日志

使用流式 Chat Completions。输入包含 model、messages、stream=true，Accept 为 text/event-stream，不设置温度或输出 token 上限。超时覆盖响应头和响应体读取，取消独立处理；限制完整线上的回复体 2 MiB（包括 SSE 元数据），底层按读取字节计数，没有换行的超长事件也不能绕过；不跟随重定向；默认仅允许 HTTPS，本机允许 HTTP。

默认 IncludeStreamUsage=true，发送标准 stream_options.include_usage；设置关闭时整个 stream_options 键省略，遇到不兼容拒绝不会自动重试。读取可选 usage.prompt_tokens、completion_tokens 和 prompt_tokens_details.cached_tokens；缺失、类型错误或负数视为未知，明确的0保留为0。原始 usage 与规范计数都写入诊断，并在成功完成时显示。格式失败的响应若有 usage 也保留。固定前缀便于兼容服务商缓存，但客户端无法承诺命中、折扣或第三方真实账单。

`StreamingResponse` 按 [WHATWG SSE 事件格式](https://html.spec.whatwg.org/multipage/server-sent-events.html#event-stream-interpretation) 解码 UTF-8，支持 BOM、LF/CRLF/CR、注释心跳与多行 data。只拼接 choices 中 index=0 的 delta.content，允许单项回复省略 index；角色和 usage 事件不当作正文，忽略其他选择的正文。finish_reason=stop 且 [DONE] 或完整事件后的正常 EOF 才算流完整；缺少结束原因、未闭合事件、异常断线或 length 均不发布建议。明确 stop 后仍追加正文视为接口结构错误。仅有正常流结束还需通过已有建议合同。

正文回调提供累计文本，首段立即通知，随后最多每100ms刷新一次，并在流结束时补齐。UI 只保留最新待显示片段，避免按 token 累积主线程队列；用请求代次和快照复查阻止取消或过期请求覆盖新内容。接收中正文与最终校验建议有明确状态区分；失败或取消后清除主面板预览，部分正文留在诊断。服务商若忽略 stream 并返回 JSON，则在同一次请求内用完整响应路径校验，标明一次性返回，不隐式重试。

分类包括 configuration、phase、authentication、http、transport、timeout、provider_json、provider_schema、provider_error、provider_encoding、stream_incomplete、empty_response、truncated、finish_reason、invalid_json、schema、contract、identity、condition、illegal_first_action、stale_snapshot。

`CallDiagnostics` 在解析前捕获成功 HTTP 的原始响应体，并在格式校验前捕获 AI 正文、finish_reason、请求 ID。校验失败也保留精确冻结输入、响应和具体首步错误。非成功 HTTP 不读取响应体；截断、取消、传输错误分别记录，不补造 AI 建议。原始响应在保留本次密钥脱敏后写入本地 diagnostics，最多保留20个本组件命名的文件。UI 最近记录用请求序号防止被旧请求覆盖；实时预览明确标注尚未发送。游戏日志仅记分类、调用ID及快照等摘要；完整诊断只能通过本地文件或用户复制分享。

诊断 response_format 区分 sse/json；stream_completed 只表示流式传输有完整结束，不代表建议合法。SSE 中断时也保留原始已读事件和已拼接正文。预览掩去本次密钥及末尾可能仍在接收的密钥前缀；拼接正文需要脱敏时，省略原始 SSE 事件体以避免从片段重建密钥，保留脱敏正文。

DiagnosticDisplay 只接收已脱敏记录，按已知层级解析日志 → request_body → messages[].content，原样展示模型消息内容和 assistant_content。不会靠替换反斜杠破坏合法 JSON / 描述。UI 不再把整份嵌套诊断追加到文本末尾；复制按钮及本地诊断保留完整记录，实时输入预览包括两个 user 段。修改展示不改变实际发送的文本或诊断存储协议。

## 预测扩展

当前只读游戏现有抽牌序列和内置固定敌人连接。未来接第三方预测器时需要注明版本、预测来源、适用快照、随机分支和失效条件，且不能临时修改真实 RNG、行动历史或 live 战斗对象。未经实现和实测的预测器不作为已经集成的能力宣传。
