# 本机更新流程

修复后由开发者执行同一个入口，避免每版临时写安装脚本、重复运行已经完成的检查。

```powershell
# 首次指定本机游戏路径；后续可省略。
./scripts/Update.ps1 -GameDir 'D:\SteamLibrary\steamapps\common\Slay the Spire 2'

# 日常交付：核心检查 → 编译/打包 → 安装。
./scripts/Update.ps1

# 先准备包，进行本次改动需要的隔离原生验证。
./scripts/Update.ps1 -BuildOnly

# 验证后安装同一份包，或游戏退出后重试安装。
./scripts/Update.ps1 -InstallOnly
```

游戏路径来自显式参数、`STS2_GAME_DIR`、本工作区上次成功使用的路径或 `GamePath.props`。本机路径、日志及缓存均写入 Git 忽略的 `work/update-local/`。

核心检查缓存比较源码、测试、构建配置和 SDK 版本的 SHA256；只有成功检查才产生记录。源码变化就重新执行检查，`-ForceTests` 可主动重跑。`-SkipTests` 是显式使用其它已记录验证的入口，不产生通过记录。默认入口不会调用长时间整场战斗基准；是否需要原生检查由实际改动决定，并验证准备安装的同一份 DLL。

构建缓存额外比较游戏引用程序集、构建脚本和随包文档。相同输入且 DLL、清单及 ZIP 哈希匹配才复用；否则调用既有 `Build.ps1 -SkipTests`，避免在构建阶段再跑一次核心检查。Git 提交本身不使缓存失效，修正文档或提交验证过的源码不会单独触发核心检查。

安装前后核对版本及 DLL/清单哈希。已安装相同文件直接成功返回；实际替换需要正式游戏退出，并为两份旧文件分别备份。替换采用文件原子替换，保留已有硬链接副本的内容；两文件更新中途失败会恢复已替换文件。更新期间安装文件被其它任务改变，或包版本低于当前安装版本，会拒绝覆盖。

安装只替换 `mods/SpireAiCoach` 内的 DLL 和清单，不运行旧缓存清理脚本，不启动或结束玩家游戏。其它路径的隔离计算实例不阻塞安装。已有 `Build.ps1`、`Install.ps1` 仍可单独调用。

每次入口执行会生成 `work/update-local/runs/<时间与唯一标识>/timeline.json`，包含检查、打包、安装的开始时间和耗时、缓存使用方式及错误；同目录保留新执行的检查/构建日志、安装前状态和安装回执。记录的总时长从入口初始化后计时，不含启动 PowerShell 进程的时间。核心/脚本检查与原生游戏验收分别记录，脚本不会自动声称完成游戏验收。

脚本自身的回归检查使用临时目录、假程序集和模拟 SDK/进程查询，不读取玩家存档、配置或密钥，不启动游戏：

```powershell
./scripts/TestUpdate.ps1
```
