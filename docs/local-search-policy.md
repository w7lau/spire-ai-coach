# 本地搜索的预算、目标与停止规则

0.7.12的两个本地按钮共用后台模拟、进度、取消与最终复核，分别选择原算法和回合前缀算法。每路最多64次整场尝试、60秒搜索、64个玩家回合，先达到相应上限即结束；准备和最终复核另计。回合探查另有计数，仍受同一个60秒预算约束。预算或回合上限中断的路线不能当作完整胜利。

## 评分范围

范围从当前操作点开始，到本场胜利及原生胜利钩子结算完成。普通比较顺序为胜利、生存、战后净生命损失、主动用药数、战后生命、最大生命、金币、回合及操作数。开启满血返回时，达到完整返回条件的路线优先于未达到的路线，防止另一计算实例的未满血候选替换已达标方案。净损失使用计算起点的生命减去完整结算后的生命，最低为0；包含战中与战后回血。过程累计扣血只作诊断，已补回的卖血不单独惩罚。

药水是备用资源，允许用药仍同时探索不用药的路线；相同净损失优先保留药水。净损失0且不耗药只达到这两个成本轴的下界，不证明额外收益最大或回合最短。格挡、意图预览、某回合的血量都不能替代完整原生结算。

## 无伤提前返回

0.7.55 将无伤返回改为**完整原生战斗结算后，玩家存活且当前生命等于当时实际生命上限**；仍要求净损血为0。起点100/200，战后100/250或150/250都不达标，250/250才达标。增加上限但没有回满、只补回起点生命、或者只是过程没扣血，都不能触发满血停止。两种算法、父池并发停止和最终候选校验共用这个条件。

「满血或最低损失即返回」沿用旧设置字段。原先严格证明最低**正数**净损失的返回保留，属于独立的损失下界证明，不会把未满血的净损失0称为满血。明确开启「找到获胜路线即返回」仍只要求完整获胜；可选消耗目标默认也要求战后满血，明确填写可承受损血阈值时保留原阈值规则。

开启满血返回后，未满血的净损失0候选仍参与战后生命、生命上限等比较，但不作为零损失/药水剪枝基准，保留后续回血分支。没有提前满足条件时继续原定预算；达到次数或时间上限仍返回最佳已知候选，并可从保留的待探索进度继续搜索。这不意味着穷举直到必定满血或已经证明无满血解。

目前按明确要求暂不为额外奖励继续搜索：RewardCoverageKnown仍未知，不是奖励机制已经全部适配，也不阻止满血返回。已允许的主动用药路线也可以触发满血返回；显式目标回合、用药限制和敌方伤害条件仍须满足。要继续比较不喝药、更短回合或其他收益，应关闭开关后点击「继续搜索」；该入口不会绕过用户保存的停止设置。

原先提出的“无伤、无药、没有额外奖励、没有未知Mod收益时才停止”方案因收益识别未实现而一直无法触发，现已由上述显式开关替代。不再把它写成当前默认行为或声称未知收益已被证明不存在。

## 继续优化与历史去重

「继续搜索」沿用刚使用的算法及原定预算，接着探索父队列保留的待探索前缀；无需先得到可执行方案。已完成任务继续去重，未完成任务归还；续跑可以发现更多前缀。预算、并发可以调整，战斗、模型/Mod、原生状态、完整历史、用药和出牌目标、回合上限必须仍严格匹配。进度只保留在当前游戏进程内，重启后重新计算。

多路分配不同操作/选择分支，每个实例保留独立原生状态。共有前缀仍需重放，去重不代表已有完整战斗检查点。先等所有搜索实例完成或确认停止，再只复核最终候选；失败的候选不能发布为可执行方案。达到预算返回已复核的最佳已知结果，尚未覆盖所有合法未来时不声称全局最优。
