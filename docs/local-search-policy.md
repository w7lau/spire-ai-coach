# 本地搜索的预算、目标与停止规则

0.7.12的两个本地按钮共用后台模拟、进度、取消与最终复核，分别选择原算法和回合前缀算法。每路最多64次整场尝试、60秒搜索、64个玩家回合，先达到相应上限即结束；准备和最终复核另计。回合探查另有计数，仍受同一个60秒预算约束。预算或回合上限中断的路线不能当作完整胜利。

## 评分范围

范围从当前操作点开始，到本场胜利及原生胜利钩子结算完成。普通比较顺序为胜利、生存、战后实际生命、主动用药数、最大生命、金币、回合及操作数。开启满血返回时，达到完整返回条件的路线优先于未达到的路线，防止另一计算实例的未满血候选替换已达标方案。生命净变化为最终生命减起点生命，保留正数回血收益；净损失仍钳制为0，用于已有损血阈值及诊断。过程累计扣血和回血量不单独计奖，反复卖血回血不能提高相同的最终结果。

允许用药仍同时探索不用药的路线；相同战后生命优先保留药水。起点50，战后60不喝药与战后75喝一次药，优先75；两条都75时优先不喝药。净损失0且不耗药不能证明额外回血已经最优。格挡、意图预览、某回合的血量都不能替代完整原生结算。

## 无伤提前返回

0.7.56 将无伤返回改为**完整原生战斗结算后，玩家存活且当前生命等于当时实际生命上限**；仍要求净损血为0。起点100/200，战后100/250或150/250都不达标，250/250才达标。增加上限但没有回满、只补回起点生命、或者只是过程没扣血，都不能触发满血停止。两种算法、父池并发停止和最终候选校验共用这个条件。

0.7.60 的「满血或最优血量即返回」沿用旧设置字段，并将完整操作历史上的损失证明扩展到实际战后血量。可信未来回复上界决定每条分支可能取得的最高生命；完整原生操作域、目标实例及有序选择逐层汇总。已经取得相同最高血量及同血量下最低用药的完整获胜路线，即可提前返回，覆盖正损失、零变化和正数回血收益。未满血的最优血量不会称为满血；未知回复、未访问分支或未完整分页保留未证明状态。所有贡献实例仍需通过收尾及运行错误检查，最终复核失败撤销结论。

明确开启「找到获胜路线即返回」仍只要求完整获胜；可选消耗目标默认仍要求战后满血，明确填写可承受损血阈值时保留原阈值规则。通用血量证明不冒充出牌次数或补刀目标证明。

开启满血返回后，未满血的净损失0候选仍参与战后生命、生命上限等比较，但不作为该模式的共享零损失基准。普通血量剪枝比较实际候选生命与可信未来回复上界；未知回复时不会只因多喝药就排除分支。没有提前满足条件时继续原定预算；达到次数或时间上限仍返回最佳已知候选，并可从保留的待探索进度继续搜索。这不意味着穷举直到必定满血或已经证明无满血解。

目前按明确要求暂不为额外奖励继续搜索：RewardCoverageKnown仍未知，不是奖励机制已经全部适配，也不阻止满血返回。已允许的主动用药路线也可以触发满血返回；显式目标回合、用药限制和敌方伤害条件仍须满足。要继续比较不喝药、更短回合或其他收益，应关闭开关后点击「继续搜索」；该入口不会绕过用户保存的停止设置。

原先提出的“无伤、无药、没有额外奖励、没有未知Mod收益时才停止”方案因收益识别未实现而一直无法触发，现已由上述显式开关替代。不再把它写成当前默认行为或声称未知收益已被证明不存在。

## 继续优化与历史去重

「继续搜索」沿用刚使用的算法及原定预算，接着探索父队列保留的待探索前缀；无需先得到可执行方案。已完成任务继续去重，未完成任务归还；续跑可以发现更多前缀。预算、并发可以调整，战斗、模型/Mod、原生状态、完整历史、用药和出牌目标、回合上限必须仍严格匹配。进度只保留在当前游戏进程内，重启后重新计算。

多路分配不同操作/选择分支，每个实例保留独立原生状态。共有前缀仍需重放，去重不代表已有完整战斗检查点。先等所有搜索实例完成或确认停止，再只复核最终候选；失败的候选不能发布为可执行方案。达到预算返回已复核的最佳已知结果，尚未覆盖所有合法未来时不声称全局最优。
