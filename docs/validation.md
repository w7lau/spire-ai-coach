## 手动验证步骤

1. 退出游戏后安装，重启，确认 Mod 列表及日志出现 `[SpireAiCoach] UI mounted`。
2. F8/F10 打开设置，输入自己的服务商配置并保存。
3. 进入战斗，展开快照，对照每个牌堆总数、同名卡数量、当前费用、效果、敌人血量和攻击意图。
4. 发起分析，确认中文建议及目标编号。分析过程中出牌，确认旧请求取消、迟到结果不覆盖新状态。
5. 关闭顶部顺序后核对快照中 draw_order_top_first 为空；清单仍保留完整卡牌。
6. 测试双击、取消、网络不可用、错误 Key、回合结束、退出战斗。
7. 加入目标 Mod，核对自定义文本、动态变量、预览值、读取限制，再评估建议效果。
8. 从此前保存战斗模式的配置启动，确认只有「分析本回合」，模型和密钥设置仍可沿用；不要求模型生成后续轮次。
9. 展开最近请求与 AI 原始回复，对照本次冻结快照ID、原始正文及失败分支。实时预览应继续单独更新；复制记录不得包含本次密钥。
10. 分析后应先看到接收中正文，再看到整理后的建议；接收中取消或改变状态，不应继续展示迟到片段。断线、超时后诊断保留部分内容但不显示正式建议。一次性 JSON 返回应显示兼容提示。
11. 模型行为对照：在没有反伤／负面触发／保留收益、仍有合法有益攻击的情况下，不应仅因伤害小而浪费剩余能量；相近状态加入真实反伤或保留能量收益后，允许说明具体理由并留能量。未实测前不将此条宣称为行为测试通过。
12. 观察胆小首次受到穿透伤害的卡牌攻击及再次攻击：首次伤害不能被事后格挡追溯抵消；used_up 随真实触发改变。连续请求核对 system_prompt_hash 一致；服务商统计没返回时显示未返回，返回0时显示0。

13. 对比同场战斗两次请求：system 和角色／遗物段相同，实时快照更新；遗物计数或使用状态改变时上下文同步更新。诊断面板可直接阅读消息，复制完整诊断仍能还原实际请求；不要将假 HTTP 测试中的 cache 数值当作真实命中。
