# 验证记录

日期：2026-10-02。

## 已执行

- .NET SDK 9.0.318，Release 编译，针对本机游戏 v0.111.0；0 warning / 0 error。
- 0.2.1 的 42 项核心回归通过：身份／首步／HTTP校验，Self 目标归一与反例、星星负数哨兵、失败原文、脱敏、截断、诊断保留。新增旧战斗模式配置兼容、本回合 HTTP 请求保留状态与遗物明细、未消费的未来输出不会进入显示；删除已取消的多轮功能测试。
- Windows DPAPI 使用虚构测试 Key 的加密、读取、普通配置不含密钥、取消记住后删除。
- 模型调用使用可控 HTTP 测试替身；不消耗真实 API 额度。
- 作者自查 Prompt → 消费字段 → parser → 纯文本 UI → 当前状态复核，无持久化游戏变化、无旧建议再注入。
- 0.1.0 的实际游戏日志已出现 UI mounted；实际请求曾失败于 illegal_first_action。用户提供的文件是输入快照而非模型原文，不能证明当时具体失败分支。
- 0.2.0 已在游戏退出状态下安装，旧 DLL 与清单已备份。安装不改变用户配置和密钥。
- 0.2.0 真实诊断确认战斗模式 HTTP 成功、正文通过合同，但只返回一条泛泛后续计划；用户因此要求收回到本回合。输入确实包含玩家 powers、relics 和敌人 powers。新版本尚未以真实模型重测战术质量。

## 手动验证步骤

1. 退出游戏后安装，重启，确认 Mod 列表及日志出现 `[SpireAiCoach] UI mounted`。
2. F8/F10 打开设置，输入自己的服务商配置并保存。
3. 进入战斗，展开快照，对照每个牌堆总数、同名卡数量、当前费用、效果、敌人血量和攻击意图。
4. 发起分析，确认中文建议及目标编号。分析过程中出牌，确认旧请求取消、迟到结果不覆盖新状态。
5. 关闭顶部顺序后核对快照中 draw_order_top_first 为空；清单仍保留完整卡牌。
6. 测试双击、取消、网络不可用、错误 Key、回合结束、退出战斗。
7. 加入目标 Mod，核对自定义文本、动态变量、预览值、读取限制，再评估建议效果。
8. 从此前保存战斗模式的配置启动，确认只有「分析本回合」，模型和密钥设置仍可沿用；不要求模型生成后续轮次。
9. 展开最近请求与 AI 原始回复，对照本次冻结快照ID、原始正文及失败分支。实时预览应继续单独更新；复制记录不得包含本次密钥。
