## 本地模拟实验（2026-10-02）

追加常驻验证：同一进程 A→B→A→B→A 从同一合成快照恢复，正常速度、时间速度 4 倍、原生 Instant、保留资源缓存及关闭房间淡入的完整检查点均与正常模式一致。两个独立进程由线程池并发调度；4 倍速度与 Instant+资源复用两组均验证了各 10 次路线执行，原生同步/RNG 指纹一致。工作目录有互斥锁；没有在同一 Godot 单例上并发执行分支。

热分支含清理/恢复耗时从正常模式中位 17.59 秒降至 Instant+资源复用约 1.5 秒，其中三张牌与敌方回合约 0.18–0.19 秒。4 倍速度两批次串行 137.42 秒、并行 75.99 秒（含启动与文件准备，一次对照）；最新 Instant+资源复用并行批次总计 48.58 秒。资源、进程已复用，战斗场景节点仍重建。16 项比较器/目录锁测试通过，最新原型构建 0 警告 / 0 错误。

尝试真实 Mod 加载后启用内部 TestMode 以移除战斗 UI，在进入战斗时失败：`Backend should not be subscribing to CombatStateChanged!`。该模式停用状态通知及相关数值重算，不是单纯的表现开关；已撤回该执行路径，未删除订阅者绕过检查。已通过的批次仍记录 Godot 资源/退出错误，未证明长期常驻无残留或全部 Mod 可恢复。详细指标见 [常驻结果](../experiments/NativeProbe/results/2026-10-02-resident.json)。

独立原型及完整结果见 [NativeProbe](../experiments/NativeProbe/README.md)。原生游戏 v0.111.0、HextechRunes 0.9.7、RitsuLib 0.6.5 的私有进程已完成固定场景出牌、敌方行动、下一回合抽牌，以及战前快照跨进程恢复。五个重放检查点的投影与原生同步指纹完全相同；带/不带 BloodArmorRune 的放血对照分别产生 3/0 覆甲。原型编译通过，证据比较器 5 项测试通过。

首阶段证据只覆盖合成单人场景与指定符文；有资源预加载/退出日志错误，常驻验证见上方追加记录。尚未接入玩家实时状态、自动搜索或所有 Mod。首阶段每条实验含启动耗时 47.49–55.32 秒，出牌至下一回合 9.47–13.16 秒。现有 AI 模组未改动、未替换安装。

## 手动验证步骤

1. 退出游戏后安装，重启，确认 Mod 列表及日志出现 `[SpireAiCoach] UI mounted`。
2. F8/F10 打开设置，输入自己的服务商配置并保存。
3. 进入战斗，展开快照，对照每个牌堆总数、同名卡数量、当前费用、效果、敌人血量和攻击意图。
4. 发起分析，确认中文建议及目标编号。分析过程中出牌，确认旧请求取消、迟到结果不覆盖新状态。
5. 关闭顶部顺序后核对快照中 draw_order_top_first 为空；清单仍保留完整卡牌。
6. 测试双击、取消、网络不可用、错误 Key、回合结束、退出战斗。
7. 加入目标 Mod，核对自定义文本、动态变量、预览值、读取限制，再评估建议效果。
8. 从此前保存战斗模式的配置启动，确认只有「分析本回合」，模型和密钥设置仍可沿用；不要求模型生成后续轮次。
9. 展开最近请求与 AI 原始回复，对照本次冻结快照ID、原始正文及失败分支。实时预览应继续单独更新；复制记录不得包含本次密钥。
10. 分析后应先看到接收中正文，再看到整理后的建议；接收中取消或改变状态，不应继续展示迟到片段。断线、超时后诊断保留部分内容但不显示正式建议。一次性 JSON 返回应显示兼容提示。
11. 模型行为对照：在没有反伤／负面触发／保留收益、仍有合法有益攻击的情况下，不应仅因伤害小而浪费剩余能量；相近状态加入真实反伤或保留能量收益后，允许说明具体理由并留能量。未实测前不将此条宣称为行为测试通过。
12. 观察胆小首次受到穿透伤害的卡牌攻击及再次攻击：首次伤害不能被事后格挡追溯抵消；used_up 随真实触发改变。连续请求核对 system_prompt_hash 一致；服务商统计没返回时显示未返回，返回0时显示0。

13. 对比同场战斗两次请求：system 和角色／遗物段相同，实时快照更新；遗物计数或使用状态改变时上下文同步更新。诊断面板可直接阅读消息，复制完整诊断仍能还原实际请求；不要将假 HTTP 测试中的 cache 数值当作真实命中。
