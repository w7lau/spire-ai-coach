# 两种算法共用的生命收益界限

0.7.55 开启满血返回时，未回满实际生命上限的净损失0路线不再发布或使用为零损失/药水剪枝基准；保留可能继续回血的路线。满血使用原生胜利钩子完成后的生命和上限，包含 Mod 上限变化；原正损失下界证明保留。共享基准同时绑定满血和首胜开关，避免不同返回目标复用不兼容界限。

0.7.43 将局部证明的优先探索扩展到第二回合及之后：已取得正损失胜利时，新算法优先执行仍缺下界的准确前缀，达到现有获胜路线的损失/用药界限就结束这次探查。局部状态下界通过完整合法域向前传播，未观察的兄弟前缀仍按乐观下界处理。普通探索继续，尝试、时间、轮数不变，局部探查不冒充完整战斗路线。

0.7.37 新增跨实例的最低净损失证明。第一回合各个合法出牌/选择分支都已经证明至少失去 12 生命、后续回复上界为 0 时，全局下界变为 12；找到完整胜利且净损失 12、不再有少喝药水的可能后，可停止其余搜索。无需把每个分支继续打到战斗结束，但第一回合仍需完整覆盖，或者已有更早的可信界限。若后续最多回复 6，则同样观测所得损失下界只能为 6。

合法操作、原生目标、卡牌实例和有序选择都保留，未覆盖操作按 0 下界计算，部分选牌页保持开放。证明按已结算试走汇总提交到父进程；它不建立独立卡牌模拟器、不省略规则钩子，也不降低尝试/时间/轮数预算。最终结论还要求所有贡献实例通过原运行错误及清理门禁；0.7.55起零净损失还须战后满血才能按无伤停止。设置名为「满血或最低损失即返回」，存储字段仍兼容旧版本。

比较基准必须是同一冻结起点已经完整结算的获胜路线。当前分支的乐观战后生命为“当前生命 + 后续回复上界”；即使乐观值仍比已有获胜路线低，才停止这条操作前缀。相等时保留其他收益的可能性；同样净损失下，已经消耗更多药水的路线可以停止。未知回复不当作零，也不比较两个未完成状态的生命来删除分支。

原生适配器读取实际模型的 IL、异步状态机及可达模型引用，不按卡名、描述或此前没观察到回血来判断机制。使用游戏自己的钩子监听模型、所有牌堆、药水与角色；生成未知模型、改变生命上限、战中或重复回血、无法读取的调用、尚未认证的效果边界均保留未知上界。代码描述按类型缓存，不执行试探性钩子，不复制卡牌效果。

固定战后回复只接受当前原生遗物的直接、无循环 `AfterCombatVictory` 回调，且金额表达式必须来自自身 `DynamicVars.Heal.BaseValue`；把所有可能调用相加，忽略条件，取得乐观上界。适配器识别实际 IL 及异步局部变量，不通过遗物 ID 匹配。已检查的 v0.111.0 命令边界按程序集 MVID 绑定，游戏更新不能自动继承证明。

第三方 Mod 的存在本身不再直接使回复界限未知。每个请求读取实际加载程序集的初始化入口、静态初始化和运行时 Harmony 回调，再沿调用和注册的委托分析；不调用这些入口或试探 Mod 钩子。外部直接或间接写入、反射、动态虚方法、未知初始化和未证明的 IL 补丁仍保持未知，原因指出具体方法。代码描述按类型缓存，全局描述每个请求只计算一次。原生模拟、任务去重与零损失后的药水消耗界限仍可使用；未知不表示卡牌不能出牌。

另有独立的实际生命账目：后台在当前生命、最大生命 setter 写入后观察，再由事件及 postfix 补充；扣血触发 Mod 回血等连续变化分别记录，重复通知不重复累计。战中、战后及增加上限后实际增加的当前生命统一进入统计。两种算法都按原生战后生命选择路线，最终复核可核对同一账目。直接写字段的变化在检查点核对并标为观察不完整；这一账目不能将“目前没回血”转成“以后最多回血 0”的证明。

父池只发布已经结束、通过后台运行错误检查的实例结果。运行中的候选仍只是探索提案，不能提供共享证明。共享内容只有净损失和药水开销等小数据，绑定请求、原生起点、模型/Mod 身份、目标与执行模式；读取限频为 100ms。其他实例不把它当作自己的路线，也不直接执行它。

新旧算法均在回合结算、用药或实际失去生命后检查同一界限。新算法的待办前缀附带已观察的回复上界；旧算法只关闭被证明无改进可能的准确操作前缀，保留兄弟出牌次序。剪掉的尝试不冒充完整试走、胜利或奖励结算。搜索预算与路线评分沿用用户设置。

结果和持久诊断分别记录剪枝、回复上界已知/未知检查、共享基准采用次数和未知原因；任务合并仍独立计数。暂未找到完整获胜基准时明确说明，避免把“剪枝 0”解释成规则已经检验并无收益。

验证：核心检查涵盖战后回复、相等分支、未知回复、上界溢出、共享身份与目标、完成状态门禁、异步 IL 和兄弟次序保留。`experiments/RecoveryBounds` 读取安装游戏的实际代码，检查常见机制及未知效果的分类，不启动战斗或遍历性能基线；它不是玩家存档下的完整模拟、剪枝正确率或提速证明。
